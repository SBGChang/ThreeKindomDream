# 33 · 戰役

> **職責**：章末的七關自動戰役。持有軍勢與糧秣、執行每一關的戰鬥、處理走留決策，
> 並在戰敗時導向中止類結局。
>
> | | |
> |---|---|
> | **owns** | `RunState.campaign` |
> | **reads** | 01 效果系統、19 名士局內、20 屬性與貨幣、21 官階、23 特質與技能 |
> | **handles** | `campaign.configure`／`campaign.engage`／`campaign.withdraw` |
> | **emits** | `campaign.stageCleared` / `campaign.withdrawn` / `campaign.defeated` / `chapter.passed` / `chapter.failed` |
> | **ownsDefinitions** | `campaign`、`battleRule`、`enemy`、`enemyCurve` |

> 決議來源見 [RFC-01](../RFC-01-campaign-rework.md) D1–D29。
> 它取代 [18 檢定引擎](18_check_engine.md) 的大檢定職責；18 縮編為只有小檢定。

## 1. 形狀

```
15 章末 ── campaign.due ──▶ 33
                            │
                     戰前配置（凍結）
                            │
              ┌─────────────▼─────────────┐
              │  第 N 關：自動戰鬥         │ ← 玩家不操作
              └─────────────┬─────────────┘
                    ┌───────┴───────┐
                 軍勢 ≤ 0        敵方全滅
                    │               │
              chapter.failed   獎勵入袋
              （25 中止結局）        │
                              ┌─────┴─────┐
                            收兵         再打一關
                              │           │
                        chapter.passed   ↑ 回到上面
```

**四條規格是這個設計的骨架**：

| | |
|---|---|
| **玩家不操作**（D1） | 技巧全投在戰前配置上，與前 8 回合用的是同一種能力 |
| **跨關不回滿**（D10） | 風險必須是玩家自己一路打出來的。若每關滿血重開，七個決策點會塌成一個 |
| **每關都可以走**（D4/D5） | 沒有及格線。**沒有任何一條路能殺死你，除了你自己按下「再打一關」** |
| **不顯示勝率**（D8） | 你已經打過前幾關，看得到自己剩多少血、上一關花了多少 |

## 2. State

```ts
type CampaignPhase = 'configuring' | 'awaitingDecision' | 'resolved';

interface CampaignState {
  readonly campaignId: CampaignId;
  readonly phase: CampaignPhase;
  readonly loadout: BattleLoadout | null;       // configuring 時為 null；engage 後凍結
  readonly host: HostState;
  readonly clearedStages: number;               // 已通過的關數 0..stages.length
  readonly banked: readonly EventReward[];      // 已保住的獎勵
}

interface BattleLoadout {
  readonly skills: readonly SkillId[];              // 主角 3 招
  readonly commanders: readonly CommanderSlot[];    // 3 位
}

interface CommanderSlot {
  readonly notableId: NotableId;
  readonly skillId: SkillId;          // 從星階開放的池裡挑一招（19 §5）
}

interface HostState {
  readonly troops: number;
  readonly troopsMax: number;
  readonly supply: number;
  readonly supplyMax: number;
  readonly buffs: readonly ActiveBuff[];
}
```

### 2.1 場上只有一支軍隊 ★

三位名士是**傳令**，不在場（D2）。推導出三件事：

1. **一條軍勢條是設定，不是簡化。** 走留決策要一眼可讀 ——
   「軍勢剩三成，下一關是頭目」就是這整個功能的核心畫面。四條血條會把它稀釋成一張表
2. **「夥伴為什麼不會倒下」不需要解釋**
3. **Buff 與恢復一律作用在軍隊上**（D23），效果強度看施術者的能力 —— 目標與來源分離

## 3. 戰前配置

| | 誰配 | 數量 |
|---|---|---|
| **主角的招** | 玩家 | 3（從已學技能中選） |
| **指揮** | 玩家選人 | 3（從本輪陣容 6 人中選，排除敵方） |
| **指揮的招** | 玩家挑一招 | 各 1（從該名士星階開放的池裡） |
| **特質** | 不用配 | 已學的全部生效 |

`loadout` 在 `campaign.engage` 首次呼叫時**凍結**。關卡之間不得更換（D「不做整補」）——
push-your-luck 的張力來自「只能帶著現有的狀態往前」。

### 3.1 星階與好感的分工 ★

| | 管什麼 |
|---|---|
| **星階** | 他有**幾招可選**（玩家挑一招） |
| **好感** | 他**多常傳令**（§4.3） |

兩條現成的軸各給一個不重複的職責，**都不碰他的數值**。「名士配置固定」的原則保住，
玩家仍然有一個小決定。同時它讓兩種跨局投資有了不同的產品：
記憶碎片（→星階）買的是**這一仗更強的夥伴**，好感買的是**你自己永久變強**（32 §5）。

## 4. 一個戰鬥回合

固定四步：

```
1. 我軍施放     擲次數 → 抽招（不重複）→ 依序施放
2. 指揮傳令     三位各自獨立擲一次 → 命中者施放其配置的那一招
3. 敵方行動
4. 判定         軍勢 ≤ 0 → 戰敗；敵方全滅 → 過關
```

**先我軍、後敵方是刻意的**：玩家的保底一招（§4.1）一定會發生至少一次，
「還沒動手就被清空」在結構上不可能。

### 4.1 主角：1 招保底 ＋ 60% ＋ 30%

三次獨立擲（D20）：

| 施放數 | 機率 |
|---|---|
| 1 招 | 28% |
| **2 招** | **54%** |
| 3 招 | 18% |

眾數落在 2 招，期望 **1.9 招／回合**。

### 4.2 先擲次數，再抽哪一招 ★

**這條規則的效果比看起來大。**

若改成「第一格保底、二三格各自擲」，玩家會把最強的一招放進第一格，
另外兩格變成彩券 —— **三格退化成一格加兩張獎券**。

次數優先、再從三招中**不重複**抽取，三格的期望上場率就相同（各約 0.63 次／回合）。
於是：

> **配置從「排優先序」變成「設計一組組合」。**

三招之間必須各自成立、互不衝突，因為你不知道哪一招會出。
這正是驗收型要的配置深度：你在組一台機器，不是排一張清單。

「不重複」也是必要的 —— 否則一個強招會靠重複抽自我放大，三格的意義又塌回去。

### 4.3 指揮：獨立擲，機率由好感決定

沿用 19 的好感五階。**`linkBonus.checkBonusByStage` 這張表原地換語意** ——
它的舊用途（大檢定出戰加值）隨 18 的縮編一併作廢，同樣五個 key：

| 好感階 | 施放機率 | 三人同階的期望 |
|---|---|---|
| 陌路 0–19 | 0% | 0 |
| 相識 20–39 | 15% | 0.45（六成回合沒人幫） |
| 友好 40–59 | 30% | 0.90 |
| 知交 60–79 | 50% | 1.50 |
| 莫逆 80–100 | 70% | **2.10**（三人齊發 34%） |

`affinityCurve.baseStartAffinity = 20` 表示所有人開局就在相識 ——
**第一場戰役就偶爾有人傳令來**，不會是死的。而有星階的名士（例：典韋 0 星 +20 → 40）
開局直接是友好，**星階的回報在第一場戰役就看得到**。

#### 好感度因此換了定位 ★

| 三人好感 | 指揮期望 | ＋主角 1.9 | 指揮佔比 |
|---|---|---|---|
| 相識 | 0.45 | 2.35 | 19% |
| 友好 | 0.90 | 2.80 | 32% |
| 知交 | 1.50 | 3.40 | 44% |
| 莫逆 | 2.10 | **4.00** | **53%** |

從相識到莫逆，**一回合的行動數幾乎翻倍**，過半數的行動來自別人。
好感不再是一個百分比加成，而是**你的軍隊每回合能做幾件事**。

這也給主角的保底一招一個明確職責：**下限由你自己保證，上限由你的關係決定。**

## 5. 算式

### 5.1 兩條資源上限

```
兵量上限 = 兵量基底 × (1.0 × T[武官階] + 0.5 × T[文官階])
糧量上限 = 糧量基底 × (0.5 × T[武官階] + 1.0 × T[文官階])

T = careerRank 的 tierMultiplier（21 提供 hostCoefficient）
```

**血量只能用功績買。經驗買不到血量**（D27）。這讓單動作回合制第一次真的有兩邊：

| 這回合 | 買到的 |
|---|---|
| 鍛鍊 → 經驗 → 數值／特質／技能 | **倍率** —— 你能打多痛 |
| 委託 → 功績 → 官階 → 兵量／糧量 | **規模** —— 你能撐多深 |

兩者**相乘**，因此都不可缺，任一策略都不會支配另一個。

### 5.2 四個效果的算式

```
施術者係數 = actorAttr / 50                   // 0–100 尺度，50 ＝ ×1.0，100 ＝ ×2.0

物理傷害 = 兵量上限 × skill.ratio × (武 / 50)
法術傷害 = 兵量上限 × skill.ratio × (智 / 50)
恢復量   = 兵量上限 × skill.ratio × (政 / 50)      並扣同量比例的糧秣
Buff幅度 = skill.ratio × (統 / 50)                 作用於軍隊
```

**傷害也按兵量比例算，這是刻意的**：你造成的傷害來自你帶的兵，武力是倍率。
一萬人衝陣比五百人衝陣傷害大。推導出的結果是整套算式**尺度一致**：

| | 隨什麼成長 | 幅度 |
|---|---|---|
| 兵量／糧量 | 官階 | 12 階間 19.8 倍 |
| 你的傷害與恢復 | 官階（規模）× 四維（倍率） | 19.8 × 2 |
| 敵方兵力與傷害 | **官階**（D25） | 由 `enemyCurve` 訂 |

於是**沒有任何一條曲線需要為個別技能重新校準** —— 只有 `enemyCurve` 一條要調。

> **敵人索引官階、不索引章節**（D25）是 [17 §6.4](17_event_slot.md) 已立的規矩：
> 難度與報酬必須一起長，否則壓低某一線的官階會變成刷簡單高報酬的農場。

### 5.3 糧秣的真正意義：你能把軍隊填回幾成 ★

因為恢復按兵量比例、且扣同量比例的糧秣：

```
有效血量 = 兵量上限 + 糧量上限 × (政 / 50)
```

用 [RFC-01 §3.4](../RFC-01-campaign-rework.md) 的係數（灰盒四章）：

| 官途 | 兵量 | 糧量 | 糧/兵 | 意思 |
|---|---|---|---|---|
| 純武 | 7.7 | 4.6 | 0.60 | 大池子，只補得回六成 |
| 雙修 | 6.3 | 6.3 | 1.00 | 補得回一整條 |
| 純文 | 4.6 | 7.7 | 1.67 | 小池子，補得回一又三分之二條 |

**三條路的有效血量在 政 ＝ 50 時完全相等（12.3／12.6／12.3），差別只在形狀** ——
純武是前重（大條、難補），純文是後重（小條、能補很多次）。

而因為 [attrLine](../content-source/core/config/training.ts) 把四維綁在官階線上
（武／統 → 武功績、智／政 → 文功績），第二維會**往自己的軸加倍**：

| | 主維（輸出） | 次維 | 次維放大的是 |
|---|---|---|---|
| 武系 | 武＝物理 | 統＝Buff | **輸出** |
| 文系 | 智＝法術 | 政＝恢復 | **續航** |

推導（兩者主維皆 A 級 85 → ×1.7）：

| | 傷害係數 | 有效血量 |
|---|---|---|
| 純武（政 E 20） | 7.7 × 1.7 ≈ **13.1** | 7.7 ＋ 4.6×0.4 ≈ 9.5 |
| 純文（政 A 85） | 4.6 × 1.7 ≈ 7.8 | 4.6 ＋ 7.7×1.7 ≈ **17.7** |

純武殺得快 1.68 倍，純文撐得久 1.86 倍。**兩條路是不同的打法，不是同一打法的強弱。**

> ⚠️ **以上全部是推導，沒有一個有實測支撐。** `兵量基底`、`糧量基底`、
> `skill.ratio` 的量級、`enemyCurve` 都未定。校準見 RFC-01 §6。

## 6. 關卡推進與走留

### 6.1 七關

`campaign.stages` 定義每一關的敵方陣容與獎勵。**內容準則**（非機制）：
每 3 關安排一位有名有姓的關底敵將，其餘填雜兵 ——
否則名士對戰的戲沒了，呂布與顏良不會出現在對面。

### 6.2 走：`campaign.withdraw`

```
banked 入帳 → phase = 'resolved' → emit chapter.passed
```

**`clearedStages === 0` 時收兵是合法的**（按兵不動）。它拿不到任何獎勵，但章節照過 ——
這正是 D5 的核心：沒有及格線。膽小的懲罰是難看的結局（D7），不是死亡。

### 6.3 留：`campaign.engage`

打下一關。`clearedStages === stages.length` 時拒絕（`campaign.completed`）——
七關打完自動結束，這一章的故事到這裡。

### 6.4 戰敗

```
軍勢 ≤ 0
  ├ 查 charge.campaignRally（天賦〈天命所歸〉：原地再起）
  │   └ 有可用 → 消耗後回復部分軍勢，繼續本關
  └ 無 → banked 全部作廢 → emit chapter.failed → 25 結局判定接手
```

**`banked` 在戰敗時全部作廢**，這是整個賭局的定價。夠殘忍的機制需要一個稀缺的
安全閥，而它已經在天賦表裡（RFC-01 §3.6）。

### 6.5 獎勵階梯

| 要求 | 理由 |
|---|---|
| 沿關卡**加速**遞增（第 7 關約值第 1 關 20 倍） | 誘惑的成長要追得上風險的成長 |
| 深處有**唯一掉落** | 純數量的獎勵會讓玩家算出「我需要 X 功績」然後在剛好夠的那一關收手 —— 貪心又變成查表 |
| 部分獎勵是**戰力**（技能解鎖、道具、好感） | 打得深 → 下一章更強 → 打得更深。早期決定因此高槓桿 |

### 6.6 收兵按鈕必須寫出放棄了什麼 ★

> 收兵（放棄：〈青釭劍〉、張遼好感 +15）

這不是新原則 —— GDD §9.5 已經寫下「避免二選一事件中玩家不知道自己放棄了碎片」。
在這裡它更重要：**看不見代價的「走」會讓 push-your-luck 退化成隨便按。**

## 7. 戰報

玩家不操作，因此**戰報是他唯一的資訊來源**（D16）。看不懂的戰報 ＝
不能玩又學不到東西，是驗收型最糟的失敗模式。

```ts
interface BattleLogEntry {
  readonly turn: number;
  readonly actor: 'host' | 'commander' | 'enemy';
  readonly actorId: NotableId | EnemyId | null;
  readonly skillId: SkillId | null;
  readonly kind: 'physical' | 'magic' | 'heal' | 'buff' | 'debuff';
  readonly amount: number;
  readonly why: readonly string[];              // 因果鏈摘要，一律可見
  readonly trace: readonly EffectTrace[];        // 完整歸因，需 flag
  readonly hostAfter: { readonly troops: number; readonly supply: number };
}
```

### 7.1 兩層可見性

沿用 18 §3.2 的分層（一律可見的結論 ／ 需解鎖的明細）：

| | 可見性 |
|---|---|
| `why`（「受〈鼓舞〉+30%」「敵方〈鐵壁〉物理 −50%」） | **一律可見** |
| `trace`（完整 `EffectTrace`） | 需 `flag.battleTrace`（天賦〈明察〉） |

因果摘要不能鎖 —— 它不是進階資訊，它是玩家改配置的依據。

### 7.2 跳過與快進第一天就要有

七場自動戰鬥第一輪好看，第五輪是阻礙。戰力明顯超過時直接秒結算、只出摘要。
玩家的實際互動節奏是：**配置 →（看或跳過）→ 走留 → 重複。**

## 8. 公開介面

```ts
interface CampaignService {
  configure(loadout: BattleLoadout, ctx: RunContext): CommandOutcome;
  // 純計算：戰前配置畫面的四人能力表（0–100 同尺）
  preview(ctx: RunContext): CampaignPreview;
  engage(ctx: TurnContext): StageOutcome;
  withdraw(ctx: RunContext): CommandOutcome;
}

interface StageOutcome {
  readonly cleared: boolean;
  readonly log: readonly BattleLogEntry[];
  readonly hostAfter: HostState;
  readonly rewards: readonly EventReward[];      // cleared 時填入
  readonly nextStage: StagePreview | null;        // 下一關的情報（不含勝率）
}
```

`engage` 收 `TurnContext`（有 RNG），`preview` / `withdraw` 收 `RunContext` ——
由型別保證預覽與收兵不消耗隨機（03 §2 的同一個手法）。

### 8.1 `StagePreview` 不含勝率

它給的是**下一關的情報**：敵人是誰、幾隻、什麼技能、頭目是哪位。
不給百分比（D8）—— 在一個玩家不操作但變數眾多的系統裡，
一個算出來的百分比是**假的精確**，玩家輸了會覺得被系統騙。

## 9. RNG 流

| 流名 | 用途 |
|---|---|
| `battle.castCount` | 主角施放次數（每回合兩擲：第二招、第三招） |
| `battle.castPick` | 從 3 招中不重複抽取 |
| `battle.command` | 每位指揮各一擲 |
| `battle.enemy` | 敵方行動 |
| `battle.drop` | 關卡獎勵掉落 |

擲的順序固定為 §4 的四步，因此同一 `(seed, cursors, state, loadout)` 必然重播出
同一場戰鬥與同一份戰報。

## 10. 規則驗證（由 02 執行）

| 規則 | 理由 |
|---|---|
| `campaign.stages` 長度為 7 | 七關是規格；長度不一致會讓獎勵階梯的反推失效 |
| 敵方強度沿關卡嚴格遞增 | 否則「越深越險」不成立 |
| 獎勵價值沿關卡**加速**遞增 | §6.5 的機制本體 |
| 至少一關的獎勵含唯一掉落 | 否則玩家算得出「夠了就停」 |
| `enemyCurve` 長度 ＝ 12（官階階數） | D25：索引官階，不索引章節 |
| `campaign.enemyNotables` 引用的名士存在 | 引用完整性 |
| `enemyNotables` 不得與該戰役的推薦指揮名單重疊 | 沿用 18 §7 的既有規則 |
| 每個 `enemy` 的技能引用存在 | 引用完整性 |
| `battleRule` 的三個施放機率 ∈ (0, 1] 且第一個為 1 | 保底一招是 §4.1 的機制本體 |

## 11. 不變量

1. `troops` / `supply` **只在戰鬥中變動**，關卡之間不回復（D10）
2. `loadout` 在首次 `engage` 後不可變更
3. `banked` 只增；**戰敗時全部作廢**
4. `clearedStages === 0` 時 `withdraw` 合法（§6.2）
5. 戰敗必然發出 `chapter.failed`，且必然在該回合導向結局
6. `preview` / `withdraw` 不消耗 RNG cursor
7. 同一 `(seed, cursors, state, loadout)` → 相同的戰鬥與相同的戰報
8. 每個戰鬥回合我軍**至少施放一招**（§4.1 的保底）
9. 恢復消耗的糧秣與回復的軍勢成固定比例（§5.3 的前提）
10. 本模組**不執行結局判定**（那是 25），只發出 `chapter.failed`

---

## 12. 刻意不做

- **不做玩家在戰鬥中操作**（D1）。要操作就要蓋第二套與養成獨立的戰鬥平衡
- **不做每人一條血條**。四條血條會把走留決策稀釋成一張表，而玩家反正不操作
- **不做名士陣亡或倒下**。更有戲，但是後續加法
- **不做關卡之間的整補**（換招、換人、回血）。張力來自「只能帶著現有狀態往前」
- **不做勝率顯示**（D8）
- **不做回合上限**（D9）。敵人的輸出本身就是時鐘
- **不做及格線**（D5）
- **不做玩家自訂技能觸發條件**。那是「設定機器」的另一層，留待戰役玩起來之後
- **不做多路線（文／武）分岔**。同一套戰鬥、不同打法（§5.3）已經是兩種玩法，成本只有一半
