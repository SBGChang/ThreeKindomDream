# 專案 UI 迭代案例

本紀錄來自截至 2026-09-13 的使用者修正。歷史例子用來說明決策，不把每次試作的形狀、尺寸或配色都固定成通則。

## 過去問題與可複用的判斷

| 使用者反饋／失敗 | 問題本質 | 下次如何做 |
|---|---|---|
| 示意图很好，實際介面卻完全不同 | 只搬位置，沒有匹配元件比例、槽感與字體 | 拆出槽、數字、圖示、人物底色逐一對照，實際縮放後驗收 |
| 金邊紙框到處都是 | 用同款容器代替系統設計 | 為能力、人物、收藏、成長系統分別選承載方式；維持共通畫風 |
| 只換中央標題，其他框沒處理 | 把紅圈誤讀成唯一修改範圍 | 通讀「大量使用」等整體意圖，列整頁重複處 |
| 中央換成紅布條仍被否決 | 改了物件，未降低容器負擔 | 可以直接呈現標題，不是每段文字都需要底板 |
| 獨立按鈕有一體感，但金屬太多 | 物件完成度與畫風是兩個維度 | 保留完整輪廓，改材質、陰影與細節密度 |
| 背景與 Q 版風格不同 | 美術檢查只看控件 | 對照角色輪廓、色塊、透視和材質，整景一致 |
| 入夢頁全塞在一起 | 資訊架構沒先分任務 | 用資質／天賦／器物 Tab；不同內容有自己的呈現方式 |
| 入夢出現同行 Tab | 依資料分類，忽略玩家流程 | 同行與入陣營是遊戲中選擇，不能因有資料就塞入前置設定 |
| 好感數字、階級與字樣太多 | 同一資訊被重複翻譯 | 主畫面握手色階＋條；詳情才解釋條件 |
| 空卡寫「獨自磨練」 | 為空狀態硬保留容器 | 沒資料就收起；只有事件時只放事件圖示 |
| 行動小圖被裁切 | 沿用直式圖改用方形裁切 | 依目標比例重畫，留武器尖端、旗面與框角安全區 |
| 所有行動 Hover 都變戰旗 | 按鈕狀態背景 shorthand 重置圖集位置 | 圖集畫在子元素，檢查全部狀態與每格 |
| 書本、官職小圖出現方底 | 素材未去背或底色處理只適合紙底 | 真透明圖示，換深木色背景驗收 |
| 文官第三階頭髮穿出帽子 | 立繪與動畫使用不同素材／遮擋 | 分開查正式立繪、動畫與 Hover 造型，不因動畫正常就略過 |
| 改成短劇但仍有舊演出 | 做成展示功能，沒有完成流程替换 | 確認實際選擇入口，删除舊正式呼叫及過時等待 |
| main 出現新經濟提案 | 新版視覺和未完成規則混用 | 對照狀態／預覽／結算；先標清介面需求，不假造實作完成 |

## 已確認的頁面語意

### 養成頁

- 中央角色與行動場景；左側能力／文武官職；右側當次參與者與事件／委託。
- 行動小圖位於左下，右侧保留給共同參與。主畫面不放多餘行旅紀錄文字列。
- 行旅手記是独立 UI，以書本圖示從「此生修為」標題右側開啟。
- 同行列表不是固定上司名單；根據目前行動變更。
- 多位參與者可延伸區域，必要時按可用高度调整；不要擋住行動或強制出現卷軸。
- 2026-09-13 最新木板／名帖版已實作，尚不能當成使用者最後定稿。

### 入夢頁

資質／天賦／器物分頁，選擇前置配置。保持角色與系統情境美術，去除重複輪迴標題、世次、小計摘要與底部分站導覽等已被刪除的冗餘區。返回與入夢是完整獨立美術按鈕；入夢可保留必要動詞。

### 風雲錄、天命閣、天工閣

- 風雲錄圍繞人物收藏、列傳與關係；人物應有足夠份量。
- 天命閣圍繞跨輪成長方向、效果與購買；花費與條件清楚。
- 天工閣圍繞藏品與器物展示；不要在空藏品時只放一張巨大通用紙框。
- 上述是系統意義，不硬性指定三頁必須相同格數、木架或卷軸。差異化素材必須仍属同一畫風。

## 新經濟提案對 UI 的影響

參考 docs/RFC-02-economy-events-rework.md，先檢查狀態是否仍為提案：

- 直接四維成長：條表示能力與上限，預測段不再表示可花的經驗。
- 本輪錢：新帳本、來源與支出到位後才換掉學習點。
- 訓練營／章節商店：局內花費入口，與跨輪天命商店分開。
- 事件星數與故事追蹤：不能用角色稀有度代替故事難度；旗標來自合法候選。
- 章末與末章：戰役後可回營整理，需要對應入口和流程。
- 新加入者：初始好感不代表完成共事／故事門檻；在詳情而非主面板堆滿計算說明。

入陣營時點、特性限制等若仍待定，不在美術任務中自行拍板。
