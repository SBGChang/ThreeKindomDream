# RFC-01 · 大檢定改為戰役制

> **狀態**：**階段 A–C 已實作**（`fba98d3` 起）。階段 D 校準未做。
> 未做的項目在 §5 逐項標了 ⬜；實測結果與未解的平衡問題見 §9。
> 本文件記錄**決議與遷移計畫**；模組契約見 [32 養成兌現](architecture/32_growth_conversion.md)、
> [33 戰役](architecture/33_campaign.md)、[23 特質與技能](architecture/23_skill.md)。

---

## 1. 一句話

**大檢定從「一次骰子判定」改為「一場七關的自動戰役」**，並補上養成與能力之間
一直缺失的那一層：**經驗值兌換**。

---

## 2. 為什麼要改

### 2.1 現況大檢定的四個問題

| # | 問題 |
|---|---|
| 1 | **六選一實際上是三選一，而三選一是在填一個風險偏好參數。** 路線那一維 8 回合前就決定了（練武的人看文路只會看到 0%），剩下三檔沿一條單調曲線走。全遊戲情緒最高的一格，是互動最少的一格 |
| 2 | **難度自選的張力只在最後一章成立。** 失敗代價是「剩下所有章節 ＋ 圓夢結局」，所以前三章貪心不是貪心，是算術錯誤。最優解恆定是「前面全穩、最後一章看情況賭」—— [policies.ts](../scripts/lib/policies.ts) 的 `rate` 策略正是這樣寫的 |
| 3 | **出戰名士是唯一的配置，卻零取捨。** 舊的 `ScreenCheck.tsx`（已刪除）預設 `eligible.slice(0, 3)` 塞滿，沒有成本、沒有排擠 |
| 4 | **那 8 回合的過程讀不到。** [roster-query.ts](../src/modules/roster-query.ts) 顯示 12 位名士在大檢定裡只貢獻一個 `sortieBonus`（1–8）。星階、碎片、好感、專長 —— 一整套系統塌縮成一個個位數的加法 |

### 2.2 一個結構性缺口

**沒有經驗值層。** [training.ts](../src/modules/training.ts) 把鍛鍊產出直接寫進
`AttributeState.values`。玩家因此沒有「這些點數要花在哪」的決策 —— 鍛鍊的產出
是既定的，不是可分配的。

**這兩件事必須一起改**：戰役制需要「特質與技能」作為配置素材，而特質與技能
需要一個購買它們的貨幣。分開做的話，任一半都不完整。

## 3. 決議記錄

以下每一條都是已定案的設計決定。**理由欄比決定欄重要** —— 它是未來想改回去時要先反駁的東西。

### 3.1 戰役的形狀

| # | 決定 | 理由 |
|---|---|---|
| D1 | 大檢定 ＝ **七關的自動戰役**，玩家在戰鬥中不操作（驗收型） | 玩家的技巧全投在**準備**上，與前 8 回合用的是同一種能力。操作型要蓋第二套與養成獨立的戰鬥平衡 |
| D2 | **場上只有一支軍隊**；三位名士是**傳令**，不在場 | 一條軍勢條因此是設定而非簡化；「夥伴為什麼不會倒下」不需要解釋 |
| D3 | 沒有三檔難度。**深度取代難度** | 難度自選從一個下拉選單變成問七次的同一個問題 |
| D4 | **每關打完都可以走**，走了保住已通過關卡的獎勵 | 見 D5 |
| D5 | **沒有及格線。** 第一關打完就走也能過章 | 這讓「走到中止結局是玩家自己貪心的結果」（GDD §8.7）**字面上為真**：沒有任何一條路能殺死你，除了你自己按下「再打一關」 |
| D6 | 輸了 ＝ **夢醒**，整輪結束 | 殘忍是這個賭局的定價 |
| D7 | 膽小的懲罰是**難看的結局**，不是死亡 | 11 個結局、官階決定稱號、結算換點數 —— 懲罰早就寫在那裡了 |
| D8 | **不顯示勝率**，玩家自己判斷 | 你已經打過前六關，看得到自己剩多少血、上一關花了多少。資訊從「系統給的數字」變成「你讀出來的」 |
| D9 | **沒有回合上限** | 敵人的輸出本身就是時鐘：打得慢就多挨幾輪。前提是 D11 |
| D10 | 血量與資源**跨關累積、不回滿** | **這是整個設計的樞紐。** 若每關滿血重開，玩家進場前就能算出該在第幾關收手，七個決策點會塌成一個 |
| D11 | **恢復是有限資源**（糧秣），不是每回合自動回 | 否則續航是無條件正解，取捨消失 |
| D12 | 獎勵曲線**加速**（第 7 關約值第 1 關的 20 倍），且**深處有唯一掉落** | 純數量的獎勵會讓玩家算出「我需要 X 功績」然後在剛好夠的那一關收手 —— 貪心又變成查表 |
| D13 | 部分獎勵是**戰力**（技能、道具、好感），兌現在下一場戰役 | 打得深 → 下一章更強 → 打得更深。早期決定因此高槓桿 |
| D14 | **收兵按鈕上必須寫著你放棄了什麼** | GDD §9.5 已立的原則（「避免玩家不知道自己放棄了碎片」）。看不見代價的「走」會讓 push-your-luck 退化成隨便按 |
| D15 | **跳過與快進第一天就要有** | 七場自動戰鬥第一輪好看，第五輪是阻礙 |
| D16 | 戰報必須是**因果鏈**，不是數字瀑布 | 驗收型玩家不操作，戰報是他**唯一**的資訊來源。看不懂的戰報 ＝ 不能玩又學不到東西 |

### 3.2 配置與施放

| # | 決定 | 理由 |
|---|---|---|
| D17 | 主角配 **3 招**；名士各帶 **1 招** | 「玩家部分比較暴力」。名士的招從他星階開放的池裡挑 |
| D18 | 四職能：**武＝物理輸出／智＝法術輸出／政＝恢復／統＝Buff** | |
| D19 | **主角不吃四職能對應** —— 四維決定他**怎麼打**，不決定他在隊裡的功能 | 沒有人想在自己的英雄故事裡當補師，而文武雙軌不能有一軌是廢的 |
| D20 | 主角每回合：**1 招保底 ＋ 第二招 60% ＋ 第三招 30%**，三次獨立擲 | 眾數落在 2 招（54%），期望 1.9 招／回合。**下限由玩家自己保證** |
| D21 | **先擲施放次數，再抽哪一招**；同回合**不重複** | 若第一格保底、二三格靠機率，玩家會把最強的招放第一格，三格退化成一格加兩張獎券。次數優先讓三格期望上場率相同（各約 0.63／回合）→ **配置從「排優先序」變成「設計一組組合」** |
| D22 | 名士每回合**各自獨立擲**，機率由**好感五階**決定 | 一回合可能三人齊發，也可能全都沉默。**上限由你的關係決定** |
| D23 | Buff 與恢復一律**作用在軍隊**上；**效果強度看施術者的能力** | |
| D24 | 恢復與 Buff 按**軍勢比例**計算，不用固定值 | 兵量在 12 階之間長 19.8 倍，比例制完全免除重新校準 |
| D25 | 敵人強度**索引官階**，不索引章節 | [17 §6.4](architecture/17_event_slot.md) 已立的規矩：難度與報酬必須一起長，否則壓低某一線的官階會變成刷簡單高報酬的農場 |
| D26 | 星階 → 他有**幾招可選**；好感 → 他**多常傳令** | 兩條現成的軸各給一個不重複的職責，都不碰他的數值。「配置固定」的原則保住，玩家仍有一個小決定 |

### 3.3 資源來源

| # | 決定 | 理由 |
|---|---|---|
| D27 | **血量只能用功績買。經驗買不到血量。** | 這讓單動作回合制第一次真的有兩邊：鍛鍊 → 經驗 → 你能打多痛；委託 → 功績 → 官階 → 你能撐多深。現在兩邊產出的是同一種東西，實測兩條路只差 12.3% |
| D28 | `兵量 = 1.0 × T[武階] + 0.5 × T[文階]`<br>`糧量 = 0.5 × T[武階] + 1.0 × T[文階]`<br>（`T` ＝ 現成的 `tierMultiplier`） | 見 §3.4。單向判定會讓文官一滴血都撐不住 —— 因為文系的續航手段（政＝恢復）全部吃糧 |
| D29 | 功績從**門檻貨幣**升級為**你的血條** | 玩家不會再覺得升官只是為了解鎖 |

### 3.4 D28 的驗算

用現成的 [tierMultiplier](../content-source/core/config/training.ts) 與
[REQUIRED](../content-source/core/career/ranks.ts)。灰盒四章單線約 2200 功績 → rank 7；
對分則兩線各約 1100 → rank 5／5。

| 官途 | 武／文階 | 兵量 | 糧量 | 合計 |
|---|---|---|---|---|
| 純武 | 7 / 1 | **7.7** | 4.6 | 12.3 |
| 雙修 | 5 / 5 | 6.3 | 6.3 | 12.6 |
| 純文 | 1 / 7 | 4.6 | **7.7** | 12.3 |

**兩個要留下記錄的性質**：

1. **總量幾乎相等（12.3 對 12.6），差別只在形狀。** 官階曲線的凸性懲罰了分散投資，
   而 0.5 那一項剛好補回來 —— 於是專一與雙修是**形狀之爭，不是強弱之爭**。
2. **0.5 那一項自帶防退化底線。** 純武官的糧量 4.6 裡有 3.6 來自他自己的武官階，
   因此「零糧秣」不可能出現，**不需要另加基底常數**。

而且因為 [attrLine](../content-source/core/config/training.ts) 已把四維綁在官階線上
（武／統 → 武功績、智／政 → 文功績），這條公式給的資源剛好是各自 kit 需要的那一種：

| | 輸出 | 續航手段 | 拿到的 |
|---|---|---|---|
| **武系** | 武＝物理 | 統＝Buff（**不吃糧**） | 大兵量、淺糧 |
| **文系** | 智＝法術 | 政＝恢復（**吃糧**） | 小兵量、深糧 |

武系靠大池子撐，文系靠把池子填回來撐。**這不是補丁，是兩套自洽的續航模型。**

### 3.5 養成兌現

| # | 決定 | 理由 |
|---|---|---|
| D30 | 四維改 **0–100** | 實況的規格。順帶帶來等級制 |
| D31 | **七個價格帶對齊七個等級**（G/F/E/D/C/B/A/S） | 玩家看到「武 B」就知道下一階要付 200 點。不用額外教學 |
| D32 | 鍛鍊產出從「屬性點」改為**四類經驗值**（武／統／智／政，不共用） | 共用一個池會讓「這回合練哪一格」失去意義 |
| D33 | 三張消耗表：**數值階梯／特質混合／技能混合** | 見 [32](architecture/32_growth_conversion.md) |
| D34 | 特質與技能用**多類混合消耗** | 純專精買不起絕階（他沒有另外兩類的經驗）。與階梯計價形成雙面夾擠 → **「S 級空手」對「A 級帶特質」** |
| D35 | **一切都要先解鎖**，含常階 | 與實況的分野（實況除金特外可直接買） |
| D36 | **名士能教的，就是他自己表上有的** | 不需要另一張「誰能教什麼」的表。名士的能力表**就是**他的教學表 |
| D37 | 解鎖**只在本輪有效**；圖鑑僅記錄「你學過什麼」 | 跨輪的預先解鎖若要做，走現有的天命商店，不在這一版 |
| D38 | 學習**不佔行動、隨時可做** | 它不是行動決策；而且數值會擋事件門檻，玩家有理由早花 |
| D39 | 道具三種降耗：**折扣／直接解鎖／階梯緩和** | 三種都接得上這次做完的 FuncType 系統 |
| D40 | 名士數值也在 **0–100** | 同一把尺，戰前配置畫面上四個人擺在一起可直接比。驗收型的資訊層靠這個成立 |

## 4. 模組配置

| # | 模組 | 動作 | State Slice |
|---|---|---|---|
| **㉜** | **養成兌現** | 🆕 新增 | `growth`（四類經驗池、已解鎖清單） |
| **㉝** | **戰役** | 🆕 新增 | `campaign`（軍勢、糧秣、關卡進度、本役已得獎勵） |
| ㉓ | **特質與技能** | ♻️ 重寫 | `skills` → 特質與技能的已學清單 |
| ⑱ | 檢定引擎 | ✂️ 縮編 | 只留小檢定；大檢定判定移交 ㉝ |
| ⑮ | 章節回合 | 🔧 改動 | 章末流程改為進入戰役 |
| ⑯ | 鍛鍊槽 | 🔧 改動 | 產出從 `attr.grant` 改為 `exp.grant` |
| ⑲ | 名士局內 | 🔧 改動 | 好感 → 施放機率；星階 → 可選招池；名士完整能力表 |
| ⑳ | 屬性貨幣 | 🔧 改動 | `attrMax` 999 → 100；不再由 ⑯ 直寫 |
| ㉑ | 官階系統 | 🔧 改動 | `checkBonus` 廢除；改出兵量／糧量係數 |

**為什麼 ㉜ 是獨立模組而不是 ⑳ 的一部分**：它是**唯一的兌換點** —— 經驗進、
數值／特質／技能出。與 ㉖ 結算是 `RunState → MetaState` 的唯一交接點同一個理由：
把單一寫入點做成模組邊界，才能斷言「產出總和 − 消耗總和 ＝ 餘額」。

**為什麼 ㉓ 是重寫而不是新增**：它已經存在、已經 owns `skills`，
而且它的「刻意不做」第三條寫著「不做主動使用技能」—— 那一條被 D17 推翻。
與其新開一個平行模組，不如把它擴為「特質與技能」。

## 5. 改動順序

分四階段。**每一階段結束時四道門禁都要綠**，不留半完成狀態。

### 階段 A · 兌換層

- ✅ 1. `attrMax` 999 → **100**；小檢定 DC 曲線與 `baseFloor` 重新標定
  （實際上內容裡**沒有任何** `statGte attr.*` 門檻，所以只有 DC 曲線要動）
- ✅ 2. 新增 `RunState.growth`；⑯ 與 ⑰ 的產出改為 `exp.grant`
- ✅ 3. 三張消耗表與 ㉜ 的 `learn.*`
- ✅ 4. ㉓ 擴為特質與技能；解鎖接上名士傳授與事件／戰役獎勵
- ⬜ 4b. **道具與官階的解鎖來源未做。** `learn.cost.*` 與 `learn.bandShift`
  兩個 target 在程式裡接好了，但沒有任何道具內容指到它們；
  `UnlockGrant`（道具直接解鎖）沒有實作。**「道具能降低學習消耗」目前是空話。**
- ✅ 5. 名士能力表（四維 0–100、特質、星階技能池）
- ✅ 6. 模擬器加經驗分配軸線（`spend`）

### 階段 B · 戰役骨架

- ✅ 7–10 全部完成。⑱ 已縮編為只有小檢定。

### 階段 C · 七關與走留

- ✅ 11. 關卡推進、跨關狀態保留、獎勵階梯
- ✅ 12. 走留畫面（含 D14 的放棄提示）
- ✅ 13. 中止結局接回 ㉕（由官階線決定戰歿／罷官）
- ✅ 14. 跳過與快進（D15）：`sweep()` 打到「開始需要想」為止，
  判準 `battleRule.sweepMargin`；戰報預設收起。

### 階段 D · 校準

- ✅ 15. 模擬器補戰役 policy。**軸線是 `margin`**（走還留要的餘裕倍數）。
- ⬜ 16. 三張消耗表、獎勵階梯、敵人曲線的校準 —— **未做**
- ⬜ 17. 重新確認專精 vs 均衡 —— **未做**

### 天賦置換

- ✅ 〈天命所歸〉→ 戰敗時原地再起（機制 ＋ 文案）
- ✅ 〈慧眼識人〉→ 戰報的完整歸因（`flag.battleTrace`，機制 ＋ 文案）

## 6. 待校準數字

**全部標 GREYBOX。** 下表列出每一項的反推依據 —— 校準時要先檢查依據還成立，
再動數字。

| 項目 | 反推依據 | 風險 |
|---|---|---|
| 數值階梯（7 帶） | 一輪總經驗約 800–1000 點；專精者單類約 650–700 → S 級（累計 740）需近乎全押 | 總經驗量本身未實測 |
| 特質／技能消耗 | 專精者站 A 帶（20／點），常階 40 ＝ 放棄 2 點數值；均衡者站 C 帶（7／點），絕階 180 ＝ 放棄 26 點 | 兩者的「有感程度」需實測 |

| 施放機率五階 | 相識 15%／友好 30%／知交 50%／莫逆 70% → 三人期望 0.45 → 2.10 | 與主角 1.9 的比值決定「好感值不值得投」 |

> **本專案的規矩**（[camp.ts](../content-source/core/chapters/camp.ts) 已立）：
> 「憑手感填一組看起來像校準過的數字，比留下明確的占位更糟。」
> 上表所有數字都附了反推過程，但**沒有一個有實測支撐**。

## 7. 會被推翻的既有校準

這些值全部反推自「鍛鍊直接加四維 ＋ 大檢定是單次 DC 判定」。兩個前提都不再成立。

| 東西 | 現值的來源 |
|---|---|
| 大檢定三檔 DC | 量出「三成回合做事」的檢定值 × 0.61／0.96／1.31 |
| `careerRank.checkBonus` | 訂在四維檢定值的一成 |
| 小檢定 DC 曲線 | 以「章中的單一相關維」為基準 |
| 事件選項與委託的四維門檻 | 0–999 尺度 |
| `trainingCurve.baseByAttr` 的**語意** | 產出是屬性點 |
| `crossLineRatio` / `trainingBaseAdd` | 官階直接抬四維成長 |
| 模擬器七策略 | 軸線是事件佔比 |

**`chapterMultiplier`（1.0 → 6.2）反而獲得了明確職責**：讓後期買得起高價位帶。
早期一回合約 15 點只夠買 F/E 帶，後期約 60 點才啃得動 A 帶的 20／點。
**成長的加速與價格的加速互相咬合。**

## 9. 實測與一個未解的平衡問題

### 9.1 模擬器（50 輪／策略）

```
策略                 圓夢率   戰役深度       特質  技能
notable-chaser       72%     3.98 關/場      5.8   2.6
flag-chaser          68%     3.60 關/場      5.2   2.6
focus-martial        56%     4.08 關/場      3.8   2.3
focus-civil          48%     3.80 關/場      3.2   2.2
risk-averse (2.4)    76%     —              輪迴點數 8554
risk-seeking (1.05)  38%     —              輪迴點數 4765
```

### 9.2 ⚠️ 貪心目前不划算

risk-averse 拿到的點數幾乎是 risk-seeking 的兩倍。**深入的報酬補不回死掉的損失** ——
因為死掉損失的是【剩下所有章節】，而一關的獎勵只是功績。

這正是本文件 §6 說模擬器要量出來的東西。**尚未處理。** 三個候選方向：

| 方向 | 賭的是什麼 |
|---|---|
| 把 `REWARD_MUL` 再拉陡 | 純經濟解。最直接，但可能讓深關的報酬失真 |
| 讓深關的唯一掉落更關鍵 | 質變解。符合 D12 的原意，但要更多內容 |
| **降低深關的變異** | 我懷疑這才是主因：一場仗只有兩三個回合，擲骰的變異相對太大，於是「算得剛剛好」實際上是輸一半 |

第三個同時會改善體感（深關要是長而磨人的仗，不是兩回合定生死），
但它會拉長戰鬥時間 —— 與 D15 的節奏顧慮互相拉扯。**這是設計決定，不是數值決定。**

### 9.3 三個實測才抓到的洞（都不會讓任何測試失敗）

1. 替身 AI 只看軍勢比例就衝，全部死在第一場（通過章節平均 0.23）。
   改成算「我撐得住幾回合 ／ 對面要打幾回合」—— 那才是人在螢幕上讀的東西。
2. 純武系把用不到的糧量算進續航，於是誤以為還撐得住。糧秣只有帶了恢復招的人算得到。
3. 關底敵將的傷害少乘 `enemyDamageRatio`，華雄一擊 1587 打玩家的 762 兵。

### 9.4 兩處內容債

- 名士的 `unlocks` 文案還在講「大檢定出戰值 +8」「大檢定通過的獎勵 +20%」。
  那些效果（`CheckValueBonus` / `CheckRewardBonus`）在戰役制下**不會被讀到** ——
  效果與文案都要換成戰役的語彙。
- `enemyNotables` 全部是空的。「選呂布當玩伴，虎牢關就不能靠他」
  這條機制在程式裡是活的，但沒有內容用它。

## 8. 刻意不做

- **不做玩家在戰鬥中操作**（D1）。要操作就要蓋第二套獨立平衡的戰鬥系統
- **不做每人一條血條**。四條血條會把走留決策稀釋成一張表，而玩家反正不操作
- **不做名士陣亡**。倒下／缺席那個版本更有戲，但它是後續加法
- **不做文武各一種戰鬥遊戲**。同一套戰鬥、不同打法（D19）就已經是兩種玩法，成本只有一半
- **不做關卡之間的整補**（換招、換人）。push-your-luck 的張力來自「只能帶著現有狀態往前」
- **不做玩家自訂技能觸發條件**。那是「設定機器」的另一層，留待戰役玩起來之後
- **不做跨輪的解鎖繼承**（D37）
