# 製作契約：把劇本接到現行遊戲

本檔是設計與工程之間的接線圖，**不是已完成的功能清單**。2026-09-14 讀取作者層與 runtime 後整理；當舊 GDD、架構文件與程式不同時，以程式描述現況，新設計另列。

## 1. 已核對的現況

| 項目 | 現況證據 | 本次設計如何處理 |
|---|---|---|
| 章節 | `content-source/core/chapters/camp.ts` 共通 1 章；`wei/chapters.ts` 魏 3 章 | 保留既有 4 個 ID，魏加 5，蜀吳各加 8，總 25 個章節定義 |
| 回合 | `src/contracts/core/state.ts` 的 TurnState 為四格選擇後處理 pending 事件佇列 | 主線事件排入既有回合節奏，不恢復舊「鍛鍊或事件擇一」 |
| 四維／貨幣 | primitives 為 lead/war/int/pol；CurrencyState 只含文武功績 | 不寫魅力、善惡值或名聲門檻 |
| 戰役 | 七關、可收兵、敗退仍過章 | 世界命運由劇情狀態決定，本隊深度決定階段成果與改命門檻 |
| 結局 | core 有 9 個定義；只有 sequenceCompleted／noFactionEligible | 新增特殊人生與國別內容，保留兩種觸發；不添加戰死出口 |
| 條件 | Condition 支援 phase/faction/chapterGte/stat/邏輯組合 | 尚不能讀劇情選擇或歷史戰役深度，需要顯式擴充 |
| 事件獎勵 | EventReward 有功績、經驗、好感、道具、boon、unlock 等 | 尚無「寫劇情選項／設定命運」獎勵；以新的敘事命令處理，勿假裝是現有 flag |
| 名士事件 | 需 cast 在陣容、好感門檻、鏈前步 seenUniqueIds | 主線不套這個可抽池；避免沒抽中角色就失去主劇情 |
| 成就 | definitions 的 DefinitionKind 無 achievement；meta 有 stats 與 collection | 架構文件的 AchievementDefinition 是方向，尚須建模與實作 |
| 內容包 | packs.ts 只有 core、wei | 新增 shu、wu 及依賴、文案、敵方資料，不只加入選國按鈕 |

工程接線檔案相對專案根目錄列出是為閱讀方便，不代表這次已修改。現有 module discipline、compiler、save migration 規則仍需遵守。

## 2. 內容規模與時間

共通 C0 一章，W1–8、S1–8、U1–8 各八章，共 **25 章、50 個 A／B 主線節點、100 個基礎選項**。每章七個戰役情境，共 175 個情境標題，實際敵人可重用。改命以既有選項擴充分支，未新增第 51 個固定節點。

每局會看到共通＋單國＝9 章、18 個主線決定，另外有最後的結局意向。R2、R6 是章內回合；跨章對照：共通 1–8，勢力第 k 章為 `8k+1` 至 `8k+8`，所以第 8 章為 65–72。

故事影片總時長須試玩驗證。初稿每章開場約 5–10 秒、每個決定約 10–20 秒、回收約 5–10 秒；終局 20–40 秒。玩家可略過已讀演出、自由回看，不強制看完整長文本才能按選項。

## 3. 主線事件佇列

主線事件在章內指定回合保證出現；畫面在選四格前就提示本回合有主線。固定事件收益照常，主線在該回合佔用**人物事件位置**，不額外再抽一則人物事件；普通委託可留在前面。順序：固定收益 → 委託（若有）→ 主線；清空佇列才可推進。

角色出場只讀劇情 cast，與可用名士陣容分離。主線選項的基礎成長兩側同級；偏向準備的選項少一份即時額外獎勵，換未來改命機會。具體功績／經驗值待 72 回合校準，不能直接把 32 回合事件表放大至 9 章而稱為平衡完成。

**B 的時間位置要拆清楚：** R6 先讓玩家選戰後承諾與預備方針；劇本中「戰後已發生」的回應台詞延至章末戰役結算後，依成功／不足播放。選擇時間與回應演出時間不是同一時間。例如先選「接到關羽後重立盟約」，只有救援成功才播放關羽上船與同意停戰；失敗改播夷陵後重修盟約，不在戰前寫入關羽已存活。

所有基礎節點列出的回應是演出草稿，不直接作立即 mutation。主線導演需支援 `choiceCommitted` 與 `aftermathPresented` 的不同時點。

## 4. 最小新增狀態提案

以下是語意草圖，不是能直接貼進現有 TypeScript 的正式型別。實作時採符合 contracts 的 branded IDs、唯讀容器與模組 ownership。

```text
Run.story
  choices: NodeId -> OptionId
  milestones: MilestoneId -> { chapterId, reachedAtStage }
  endingIntent: personal | factionPolicy(policyId) | commemorate(routeId)
  personalIntent: legacy | retire | teach | shelter | resign
  pendingSceneIds: SceneId[]
  presentedSceneIds: SceneId[]

Run.campaignHistory
  ChapterId -> { campaignId, maxCleared, closeReason }

Meta.narrative
  seenScenes: Set<SceneId>
  completedRoutes: Set<RouteId>
  endingRecords: Set<(endingId, contentVersion)>

Meta.achievements
  unlocked: AchievementId -> { runId, unlockedAt }
```

`choices` 對同節點只能成功提交一次。`milestones` 只記不可逆成果，例如「關羽已救出」；「此線是否完整」由 choices、里程碑與序列完成推導，不再另存一套會失同步的 completed 布林。

`campaignHistory` 是已結束或已取得里程碑的實績；不能用目前 `CampaignState` 去猜上一章打到第幾關。到閾值就落盤 milestone，後續敗退不回滾。

存檔需要一個穩定 runId。相同 seed 可以重開成另一局，重播同一局不能冒充新局。既有 `settledSeeds` 的防重設計必須評估遷移，不能只用新 runId 繞過舊結算冪等機制。

角色生死從故事里程碑及章序推導，劇情導演只從這個查詢讀取。未救到的名士若仍在既有可用陣容，戰鬥定位為夢境保留的「名士投影」，不當作故事肉身仍在世；相應顯示與過場稱呼必須交代。若未來決定真人陣亡會退出可用陣容，那是另一個涉及養成補償的機制變更，本版不採用。

## 5. 條件擴充及結局判定

應提供可驗證的條件：選項已選、里程碑已達、指定章深度至少 N、對固定節點集合計數至少 N、結局意向一致。章節條件用 chapterId，不能用絕對回合猜是哪一國第幾章。

主線分支戰役必須在開始配置前定案。S7 救援／守岸、U3 救援／守城使用同一章的兩個情境版本，不在玩家配置後偷偷換敵人。若現行章戰役一對一驗證不容許版本，新增 scenario 定義層，不複製章節 ID 或破壞序列唯一性。

結局依序處理：

1. 序列結束前等待終章 B 回應演出、意向確認，避免 `sequence.completed` 先結算吞掉選擇。
2. 計算本局所有完整改命；若意向是紀念且其路線完整，取該結局；否則有改命就取全域 priority 最高者。
3. 無改命時，嘗試意向指定的常規勢力結局；無合格者就回個人意向頁顯示缺項，不默默替玩家改選。
4. 個人歸宿按通用特殊人生與官階優先級判定；所有合法狀態有功成兜底。
5. 計算官途副標，與主結局一起展示。只有主結局寫入結局收藏。
6. 本次乘數＝max(主結局乘數, 依官階推導的通用官途乘數)。官途乘數只看官階候選，不讀特殊人生意向。兩者都沒有特殊門檻時使用功成 1.2；布衣若命中則依其 1.0，而非一律與兜底 1.2 取最大。這等於先按官途規則選出唯一結果，再拿該結果的乘數比較。
7. 結局演完才夢醒、結算、收集與成就。持續存檔要能在演出中恢復，不重發獎勵。

對第 6 點：掛印長歌 C=2/M=1 的官途為功成，故最終可得 max(1.05,1.2)=1.2；C=1/M=1 的官途為布衣，故掛印主結局得 1.05。表內倍率是主結局自己的值，最終預覽必須顯示比較後結果。若沿用現有固定 EndingDef.pointsMultiplier，需擴充結算輸入來承接此規則，不能只改資料。

`isFullDream` 仍按主結局類型；完整 9 章進度另以 sequence completion 統計。舊架構把圓夢＝通關與低官階未圓夢同時寫入，實作時必須消除這項矛盾。

## 6. 通用人生標記對照

不加自由累積的「善惡值」。只計固定節點集合，每章去重；同章 A、B 都護民仍只算一章。其他地方的友善台詞不自動算條件。

| 路線 | 護民節點（任一條件成立即該章計 1） | 交接節點 |
|---|---|---|
| 共通 | C0.A=shelter 或 C0.B=return | C0.B=handover |
| 魏 | W1.B=shelter；W4.A=boats 或 W4.B=evacuate；W5.A=settle；W6.B=shelter；W8.A=shelter | W1–W8 任一 B=handover（每章各 1） |
| 蜀 | S1.A=rescue 或 S1.B=shelter；S2.A=granary 或 S2.B=shelter；S3.A=rescue 或 S3.B=shelter；S4.B=shelter；S5.A=granary | S1–S8 任一 B=handover（每章各 1） |
| 吳 | U1.B=shelter；U2.B=harbor；U4.B=shelter；U5.B=shelter；U6.A=shelter；U7.A=harbor；U8.A=shelter | U1–U8 任一 B=handover（每章各 1） |

例如解鎖授業只需三個不同章交接，不要求本局集滿所有名士或改寫歷史。

以下是設計上存在的條件組合；官階數值與第五關戰力仍須以真正的平衡模擬證明可以養成。不得把條件可滿足等同實測通關。

| 布衣 | C=1/M=1，個人 legacy，沒有完整改命 |
| 掛印長歌 | C=2/M=1，個人 resign，沒有完整改命 |
| 尚書 | C=3/M=1，個人 legacy，無改命 |

| 丞相 | C=6/M=1，個人 legacy，無改命 |
| 大將軍 | C=1/M=6，個人 legacy，無改命 |
| 出將入相 | C=5/M=5，個人 legacy，無改命 |
| 解甲歸田 | C=3/M=1，個人 retire，無改命 |
| 桃李成蹊 | C0.B、W1.B、W2.B=handover，個人 teach，無改命 |
| 萬家燈火 | C0.A=shelter、W1.B=shelter、W5.A=settle，個人 shelter，無改命 |

| 吳雙改命 | U2.A=scouts；U3 escort/handover；U7 charter/handover；U8 hearing/handover；U3、U8 深度≥5 |

國策可達性：三個候選分屬不同節點，可取其中任意兩個並選對意向。三種國策同時符合也不衝突，因最後意向只選一個。若為避免改命自動優先，任一必要改命節點選其基礎替代方案即可。

保留的在野無正常入門見證，標為 legacy，不納首發 26 結局或成就分母。舊結局、舊 32 回合序列須帶版本，不能直接冒充新版 9 章通關。

## 8. 平衡與文字必查事項

- 章序擴大到 9 章，需要檢查 chapterMultiplier、敵人章序縮放、官階收入與上限、技能經驗、輪迴點公式；不可只擴 chapters 陣列。
- 主線兩側基礎收益同級，準備選項的額外收益差額不超過該章一次普通委託預期收益。實際數值需測，不能讓改命準備導致永遠打不到五關。
- 初階、進階、成熟天命各測一套，四維專精與混合配置都要能完成至少一條改命；雙改命是中後期挑戰，不能宣稱首輪必過。
- 角色條件枚舉：郭嘉生／死；關羽生／死及盟約成／未成；孫策生／死及分工成／未成；孔明改命成／未成；朝議成／未成。所有後續場景從同一查詢選變體。
- 主角戰敗不可接「你已戰死」文案。NPC 基線死亡與玩家敗退分開敘述，不以本隊通關深度回溯抹除已成立的救援。
- 章內跨年用過場明示；孫堅不出現在孫權晚年，孫登不處理自己死後的爭儲，已亡人物僅能以有標記的回憶／夢影登場。
- 孔明夢中復興的蒙太奇需要至少「交接運作 → 多次推進 → 城門開啟」三段，不用五丈原一勝直接跳成天下統一。
- 七關情境中的「追擊」「接應」與改命閾值一致。救援第五關成功後，六七關一定是擴大成果或斷後，不能重新要求救同一個人。

## 9. 實作批次與驗收出口

### 批次 A：敘事骨架＋蜀三章切片

補主線定時事件、選擇紀錄、決勝里程碑、戰役變體、延後結局與回看。用 S6–S8 開發切片驗證「S7 第五關救出 → 第六關敗退 → 關羽仍活著 → S8 出場」。前置只用明示開發 fixture 提供；正式遊戲不得偷送。

同時做 S7 未準備、準備但未過五關、救出未和解、完整改命四個結局路徑。做到這裡才證明支線結構可用。

### 批次 B：通用與國策結局

新增 3 通用條目、修正罷官語意與功成遮蔽、加入 9 國策結局、官途副標及單倍率規則。驗收兩個觸發均有空門檻兜底、所有可收藏結局有見證、舊檔不誤授新語意成就。

### 批次 C：三國完整內容包

補齊魏 8、蜀 8、吳 8 章與相應名士、技能、委託、敵人、文案。逐國跑完整 72 回合，所有 A／B 節點恰好出現一次，劇情不會因隨機人物事件擠出佇列。

### 批次 D：改命與成就全量

實作六改命與 42 成就，驗收每國雙改命的可共存性、紀念選擇、失敗保留、存檔恢復、成就防重，以及固定版本的全收集分母。

### 每次程式落地後的檢查

作者層內容編譯、typecheck、content／discipline／modules 門禁；新增敘事狀態的存檔遷移；針對分支、敗退保留與結算冪等的少量行為測試；72 回合平衡模擬。門禁通過之後再用實際畫面讀一次完整劇本，檢查章末戰役、回應與夢醒順序。
