# 一般事件的單挑、舌戰與小型戰場

日期：2026-09-18。狀態：三種一般事件挑戰已接入正式流程，採用事件與驗收見第 8 節。

本案補充既有 IF 劇本與《戰場故事、選項與特殊獎勵企畫》。事件規模與檢定玩法分開定義，不能因為使用單挑、舌戰，就強制玩家先進戰場。

## 1. 確定規則

### 使用原則：按劇情需要少量加入

小檢定是可選的事件呈現方式，不是所有事件的標準流程。是否採用由個別橋段的敘事與節奏判斷，不設每章或每名武將必須出現的配額。

- 保留純對話、選擇與原有數值檢定；日常相處、情感交流、資訊交代、領取成果通常不追加可操作挑戰。
- 只有玩家親自出手能增加張力、讓人物關係更具體，或讓重要承諾得到實際驗證時，才考慮單挑、舌戰或小型戰場。
- 一句對話或一次選擇能充分表達的內容，不為了使用玩法硬加戰鬥；已由章節戰役表現的成果也不重複考一次。
- 避免相鄰事件連續要求操作檢定，讓重要挑戰之間保留養成與對話的呼吸空間。這是編排判斷，並非新增隨機跳過規則。
- 下方事件表僅為候選方案，不是全數實作清單；正式逐筆審稿時可保留原呈現、不加挑戰。三種玩法的首批驗證也不代表之後每章都要配置三種挑戰。

| 事件類型 | 流程 | 事前配置 |
|---|---|---|
| 一般事件・單挑 | 養成對話／選項 → 單挑場內對話 → 實際單挑 → 結果對話 → 返回原流程 | 無戰場配置；沿用主角當前能力、裝備與單挑規則 |
| 一般事件・舌戰 | 養成對話／選項 → 舌戰場內對話 → 實際舌戰 → 結果對話 → 返回原流程 | 無戰場配置；沿用主角當前能力與舌戰規則 |
| 一般事件・戰場 | 養成對話／選項 → 簡易整備 → 玩家一隊對敵方多隊 → 結果對話 → 返回原流程 | 只選自己的技能與士兵配比 |
| 大檢定／章節戰役 | 保留既有正式整備、戰役與關內故事流程 | 保留現有完整配置 |

「一挑 N」本案按玩家主將帶一支部隊、對敵方 N 支部隊解讀，不是主角徒步單人砍 N 名士兵。同行武將可出現在對話，不額外生成可配置的友軍隊伍。

一般戰場的 N 由事件資料指定，初版以同場多隊為預設；不複製章節七關或無限波次。N、敵軍總兵力及能力須一起計算難度，不能只以隊數代表強度。

## 2. 保留篇幅、成本與劇情因果

- 共同序章、三線各八章、原養成行動數、章節戰役關數不變。
- 在既有事件位置替換檢定方式，不在該位置之後再插一場額外事件；事件原本消耗的行動只扣一次。章末延後回收的節點仍在原回收時機結算。
- 一般事件勝利只決定該事件的成功出口，不直接增加章節戰役深度、不跳章、不等於贏下赤壁或完成救援全套條件。
- 選擇紀錄與挑戰成果分開保存。例如選「護送醫舟」只代表接下任務，勝利後才寫入「醫舟護送完成」。
- IF 所需的前置準備、人物狀態及後續門檻仍有效。同行者已在隊中時要選同行版劇本，不可又扮演敵人或重演死亡。
- 不因改成可操作檢定而額外給一份戰場通關獎勵、擊殺金錢或碎片；沿用原事件成功／失敗預算。既已批准的全盛／疲勞呂布特殊獎勵照原案保留，不能被本條取消。
- 挑戰能力可由養成影響；不是按下出戰後再做一次相同的隱藏數值骰。玩法的實際勝負就是本次檢定結果。

## 3. 簡易整備介面

採單張橫向軍案，不套用大戰役情報面板。只有自己的技能、士兵配比與出陣控制。

```text
┌────────────── 手繪軍案／布卷 ──────────────┐
│                  整備出陣                 │
│                                          │
│  主角立繪        本次攜帶技能              │
│                  [技能圖][技能圖][空槽]   │
│                  （槽位沿用當前解鎖數）    │
│                                          │
│  己方兵力        [步兵圖]  [弓兵圖]        │
│  固定總量        [減][配比][加]            │
│                                          │
│          [返回]             [出陣]         │
└──────────────────────────────────────────┘
```

- 技能從已學會技能中選，槽數、互斥與重複限制沿用正式配置規則；未學會的技能不展示成可選項。
- 士兵配比只調整現有可用兵種（初版步兵／弓兵），兩者合計始終為 100%；整數兵數由比例分配後補齊尾差，不可憑調整多出兵。
- 總兵力依事件兵力規則及玩家當前可用上限確定，不提供擴軍、買兵、選友將或陣型頁。事件借兵若有，須明確是本事件暫借。
- 首次配置以最近一次合法配置為預設；沒有可選技能時可無技能出陣，不阻塞事件。
- 不顯示敵方名單、敵方兵種、敵方能力、地圖、波次、戰利品預覽、難度評分或戰場情報欄。
- 故事中的任務目標仍需在對話交代清楚。戰中維持必要的操作與勝負資訊，不能因整備介面簡化而讓玩家不知如何獲勝。
- 主角立繪、技能槽、兵種圖示、配比控制與出陣牌都要使用遊戲美術資產；沿用粗線條 Q 版、木案、布卷、玉牌，不以普通表單或純色方框交付。
- Hover 保留美術底圖，只做局部提亮；禁用以壓灰呈現，不能整片泛白。鍵盤焦點與點選區必須清楚。

返回配置前對話不算敗北、不發獎、不重抽事件。若該段有「不接任務」選項，從對話走對應出口；已承諾的強制劇情只能暫停，不能靠關閉配置跳過。

## 4. 適合採用的事件方案

以下為新增玩法的候選段落，不代表目前這些名稱都已有可直接綁定的事件 ID。正式接線時逐筆對應既有事件槽與出口，避免把已在大檢定內的故事搬出來再演一次。

| 路線／段落 | 一般事件候選 | 檢定 | 成功／失敗的局部回收 |
|---|---|---|---|
| 共通・倉門裡的人 | 選「奪外寨斷援」後搶通側路 | 1 對 N 戰場 | 控制通道／通道未清，轉走救人撤離的失敗回應；不提前結算章末戰役 |
| 魏・官渡前 | 夜襲轉運小隊 | 1 對 N 戰場 | 帶回運糧情報／情報不完整；不直接判定官渡勝利 |
| 魏・河北 | 軍議上爭取郭嘉休整與醫隊接力 | 舌戰 | 取得輪調支持／需接受原部署；單次說服不能取代全部救援門檻 |
| 魏・成都新線 | 接觸劉璋部屬、辯明接管條件 | 舌戰 | 得到地方承諾／遭拒，保留本章原分支出口 |
| 魏・北拒匈奴 | 邊境首領試武 | 單挑 | 取得會面資格／失去此次資格；不以試武勝利宣告邊境全勝 |
| 魏・治世、西域 | 商路使者議約 | 舌戰 | 落實互市條件／議約未成；西域最終大檢定仍留原章末 |
| 蜀・入蜀 | 偵路小隊遭截擊 | 1 對 N 戰場 | 帶回伏兵線索／偵路失利；落鳳坡是否救成仍看完整準備 |
| 蜀・武將相交 | 趙雲或馬超的營中切磋 | 單挑 | 得到武藝認可／敗而受指點；按人物事件原預算結算 |
| 蜀・荊襄會盟 | 邊界與糧道議約 | 舌戰 | 取得使者支持／盟約條款未定；保留後續會盟門檻 |
| 蜀・麥城前 | 護送接應物資通過封鎖 | 1 對 N 戰場 | 接應物資就位／缺少該項準備；隊中有關羽時改為共同救前軍 |
| 蜀・中興漢室 | 故都官署交接前的朝議 | 舌戰 | 爭取交接支持／留下反對意見；中興結局仍由終章條件決定 |
| 吳・江東 | 太史慈依約比武 | 單挑 | 彼此認可／保留敗後再會台詞；不額外兌換角色資格 |
| 吳・荊淮 | 爭取周瑜交令與輪值 | 舌戰 | 交令獲支持／仍有疑慮；救援結果不在此直接兌現 |
| 吳・江岸止兵 | 兩軍使者核驗戰俘交還 | 舌戰 | 化解爭議／交還受阻；不是再打一遍夷陵 |
| 吳・兩岸立政 | 港口補給被截 | 1 對 N 戰場 | 接回物資／補給受損；不增加一關港口戰役 |
| 吳・大航海 | 出航前的通商條件商談 | 舌戰 | 建立港口約定／需另尋合作；保留終章海上劇情 |

優先落地：一場營中切磋、一場輪調舌戰、一場護送小戰場，用三種一般事件確認流程；其餘候選只在敘事需要時採用，不全面移植。每段至少有挑戰前台詞、玩法內開場台詞、成功與失敗回應。友好切磋不使用死亡台詞，外交舌戰不使用對方軍隊敗退台詞。

呂布虎牢邀戰、已設定接戰後觸發的救援與海上通商場內故事，仍屬「大檢定內事件」。它們繼續暫停並返回原戰場，不因本補案一律變成獨立場景。

## 5. 結果與返回

每筆挑戰必填成功、失敗、平手／超時、撤退出口。玩法不存在的結果可明確標記不適用；不得默認所有出口都是成功。一般事件失敗返回原事件失敗回應，不自動終止整輪夢境。

普通戰場初版以擊退全部敵隊為勝、己方敗退為敗；有時間上限時須寫清超時出口。護送題材可先以「清除攔路敵軍」表達，未實作護送單位前不能宣稱有護送 AI。

單挑與舌戰直接建立自身的對決快照，不生成空白戰場、不出現兩軍接戰轉場、不等不存在的戰場計時器恢復。

生命、體力與兵損預設只在本事件快照內使用；是否影響正式資源由事件顯式結果效果決定，不能讓共用戰鬥引擎暗中多扣一次。取消、重進與讀檔不重骰、不重發獎。

## 6. 資料驅動與接線契約

提議的事件挑戰資料（欄位為設計稿，不代表現有 schema 已支援）：

```ts
type EventChallenge = {
  scope: 'event' | 'campaign';
  mode: 'duel' | 'debate' | 'battle';
  entry: 'direct' | 'simplePrep' | 'fieldTrigger';
  challengeId: string;
  opponentProfile: string;
  battle?: {
    allySquads: 1;
    enemySquads: readonly string[];
    troopBudgetRule: string;
    skillLoadoutRule: string;
    objective: 'defeatAll';
  };
  openingDialogue: string;
  outcomes: { win: string; lose: string; draw: string; retreat: string };
  rewardPolicy: 'eventOnly';
};
```

一般事件的 duel／debate 必須 direct，battle 必須 simplePrep、己方一隊、敵方多隊；fieldTrigger 保留給既有大戰場故事。敵人與難度資料仍存在後端，只是不在簡易整備 UI 展示。

事件執行器保存：原流程返回點、事件實例與版本、已選選項、一次性的行動消耗、準備配置、隨機狀態、對決快照、結果與獎勵紀錄。結算只在一個入口執行，UI 關閉不能代替勝負回報。

原提案階段僅交付企劃；本次實作狀態見第 8 節。沿用現有單挑／舌戰引擎，但不能沿用其「一定有父戰場」的假設。

## 7. 驗收

1. 從養成觸發一般單挑／舌戰，直接看到對應場景，過程中沒有戰場整備或戰場背景。
2. 一般戰場只有主角一隊；配置頁只含自己的技能、兵種配比及必要控制。
3. 未學技能不能裝、總兵力不因比例改變、沒有可選技能也能出陣。
4. 三種玩法的勝、敗、平手／超時、撤退都回正確事件出口；不多消耗行動或推進章節。
5. 救援前置未滿時，贏一場一般挑戰也不能直接解鎖人物或 IF 結局。
6. 戰場內的三英戰呂布仍在接戰後觸發，結束能回原戰場。
7. 存檔重開、重複點擊與轉場中止不重發獎勵、不重抽對手。
8. 簡易整備使用正式美術，Hover、停用、焦點與小視窗縮放均有視覺驗收。

## 8. 已接入遊戲（2026-09-18）

一般事件挑戰已從企劃接入正式養成事件流程；不是只在體驗頁演出。事件選項可帶 `challenge`，定義與驗證器分別位於 `src/contracts/core/event-challenge.ts`、`src/data-runtime/event-challenge-validation.ts`。前文第 6 節為早期提案，實際欄位以這份契約為準。

本次採用 6 則既有事件、7 個選項，沒有新增事件槽、章節或回合：

| 既有事件 | 採用選項 | 玩法 |
|---|---|---|
| 共通・押運 | 親率突圍 | 主角一軍對三支賊兵，同場交戰 |
| 共通・叫陣 | 出陣應戰／賭退兵三十里 | 單挑；兩選項難度不同 |
| 共通・獻策 | 當眾辯明利害 | 舌戰 |
| 魏・郭嘉的一個賭 | 辯明敵軍動向 | 舌戰 |
| 蜀・馬超相交 | 營中切磋請教 | 單挑，友好收手 |
| 吳・張昭相交 | 辯明新政利弊 | 舌戰 |

其餘候選並非待強制補齊的清單，保持原劇情與 IF 條件；沒有敘事需要的日常選項仍直接結算。

- 對話交代挑戰、選項標示模式，再進入真正的單挑／舌戰／戰場。單挑使用演武場景，不建空戰場。
- 戰場先進入營帳書冊整備，最多三個已學技能、步弓比例；不展示敵方資料。敵隊同時在場，各有自己的兵力分組，勝利不生成下一波。
- 初版預選前三個已學技能、步兵 60%；本次整備的改動可存檔。尚未加入跨事件沿用上次配置。
- 普通戰場有時限，必須在時限內擊退所有敵隊；雙方仍存活而時間到，走平手出口。單挑平手、主動認退均走未成結算；舌戰沿用心防歸零分勝負。
- 實際結果取代該選項原本的機率檢定，獎勵仍由既有事件預算支付；不另給戰場擊殺金、不追加回合、不改救援或角色解鎖條件。
- 快照保存選項、亂數、手牌、單挑交鋒、戰場與配置。重開先暫停，繼續原局；已結算選項不能再次領取。
- 簡易整備採用現有營帳、書冊、紙牌與玉牌美術，未增加不一致的新畫風。

開發環境體驗入口（獨立記憶體局，不改玩家存檔）：

- `?art=event-challenge&mode=battle`：押運，選第二項。
- `?art=event-challenge&mode=duel`：叫陣，選第二或第三項。
- `?art=event-challenge&mode=debate`：獻策，選第三項。

驗收包含完整回歸、三模式實際瀏覽器操作，以及新增的挑戰測試：流程隔離、配置限制、確定性、戰鬥讀檔、撤退／勝敗／超時、只結算一次、舊存檔相容及無效資料拒絕。
