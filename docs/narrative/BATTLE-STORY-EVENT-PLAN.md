# 戰場故事、選項與特殊獎勵企畫

2026-09-18 補充：[一般事件檢定企劃](EVENT-CHALLENGE-PLAN.md)區分一般事件與大戰場內事件。一般單挑／舌戰不必先進戰場；本文虎牢接戰觸發流程仍保留。

版本：第二版，實際戰場接戰觸發，2026-09-17。

試玩入口：啟動 Vite 後開啟 `/?art=battle-story`，直接進第一關虎牢的實際即時戰場，不必從養成開局。先看到軍隊入場、列陣、前進，步兵真正交手後才觸發故事，沒有開場直接讀劇本。假資料位於 `public/demo/hulao-story.json`。這是獨立戰場試玩，不修改正式夢境或存檔；尚未把新節點部署到所有國線。

已撤掉第一版的網頁式對話卡片、獨立人物畫布與三個簡化出招按鈕。現版共用養成故事的 `DialogueActor`、`DialogueFace`、`DialogueText`、對話框與選項樣式；單挑共用正式的動作演出與 `DuelBattleOverlay` 操作盤。原戰場保持在對話背後，對話與對決結束後回到同一份戰場狀態。拒絕挑戰則繼續原關卡；玩家單挑勝敗才會使相應軍隊撤退，三英演武不結算整軍。

## 一、長度與預算的補充規則

仍維持共同序章＋八章、每章七關與原養成回合。新增的是「關卡內的故事與對決」，不另起第八關、不消耗或增加養成回合。原企畫的十八個決策指養成 A／B；本案依最新需求另允許戰場選項，不能再把所有選項合計限制成十八個。

戰場對話、選項、單挑、舌戰與結果演出期間，主戰場計時和兵力模擬暫停，結束後僅恢復一次。拒絕挑戰不是自動戰敗，返回該節點的指定出口；失敗是否敗退、降低戰果或返回戰場，都由節點明列。

本次明確增加「特殊挑戰獎勵」，是先前不加 IF 額外資源原則的例外。維持章數並不代表數值預算毫無改變：四維各＋5、名器與黃金500都要列入未來平衡試算。暫照提案實現，不暗自削減。正式版需區分本章基礎獎勵、挑戰獎勵、角色資格，各自防止重發。

## 二、虎牢第一關完整流程

1. 兩軍入場→步兵接戰→暫停戰場→呂布邀戰→玩家第一次選擇。
2. 立即出陣：滿血、完整能力的呂布，沒有三英演武增益，也沒有疲勞。主角沒有揚名增益。
3. 暫不出陣：張飛→關羽→劉備，三場雙方自動交鋒；每場之間有敗退與呂布心聲。
4. 三英敗退→呂布點名玩家→第二次選擇。
5. 接戰：單挑場內先播放呂布與玩家心聲，之後才開放出招。第三合另有疲憊對話，讀完才繼續。
6. 拒絕：本段結束，正式接線時回原關卡；不發單挑獎勵、不額外扣能力。
7. 勝利→獎勵→人物認可→回戰場／本段結尾。失敗與平手都有獨立出口，不發勝利獎勵。

| 對局 | 呂布狀態 | 玩家／對手 | 性質 |
|---|---|---|---|
| 提前挑戰 | 100%生命，無額外增益 | 早期主角，無額外增益 | 玩家實際出招、真實勝負 |
| 張飛出戰 | 戰鬥力×2 | 張飛自動出招 | 使用現有單挑規則與固定種子 |
| 關羽接戰 | 只提高攻擊×1.5，清除前場×2 | 關羽自動出招 | 同上 |
| 劉備接應 | 清除前場增益 | 劉備自動出招 | 同上 |
| 稍後挑戰 | 開場50%生命，戰鬥力×0.8 | 主角戰鬥力×1.2 | 玩家實際出招、真實勝負 |

本原型的「戰鬥力」＝本場基礎攻擊與防禦一同乘倍率；不修改四維、最大生命、體力或正式養成能力。「攻擊力」倍率只改攻擊。所有修正從原始角色重新計算，不能在×2上繼續乘×1.5，或把疲勞帶回角色養成。

三場演武各自使用完整對局快照，血量不逐場繼承；疲憊藉由台詞、逐場降低增益與最後50%生命表現。這是原型的明確規則，不把血量快照偽稱連續物理損傷模擬。若後續改成連戰繼承，須再校準三將戰果與最後半血門檻。

雙方都由模型實際結算；NPC我方的AI只讀自身公開可用招式與資料中的權重，不偷看對方已鎖定招式。固定種子使這份演出資料可重播，已驗證三將都敗退。若作者改資料使戰果逆轉，走「演出結果改變」出口，不能繼續播放敗者成為勝者的矛盾台詞。

### 獎勵

- 提前擊敗全盛呂布：全屬性各＋5（沿現有上限100）、方天化戟、赤兔馬、呂布相逢資格。能力立即在該勝利節點入帳。
- 返回本陣，曹操稱許→青虹劍、倚天劍、黃金500；與前一份獎勵分開登錄，但各自只發一次。
- 擊敗疲憊呂布：方天化戟、赤兔馬、呂布相逢資格；不發全屬性＋5、曹操雙劍與黃金。
- 失敗、拒絕、平手：無上述勝利獎勵。首次選提前挑戰而失敗，不能接著再領一次疲勞版機會。

道具名稱依本次提案保留「方天化戟」「青虹劍」。示範道具只記錄名稱，尚未配置正式裝備效果、資產 ID 或自動裝備規則。

## 三、重要節點的演出規劃

每個重要節點至少有進場對話與結果回應。不是每段都一定單挑；文臣、盟約與治理問題應用舌戰或選擇呈現。以下為企畫，除虎牢外尚未實作。

|---|---|---|---|
| 宛城接典韋 | 典韋斷後、營門起火 | 玩家單挑追將／優先護送；準備不足時不假稱救成 | 救援資格；單挑可有名器，獨立門檻待定 |

## 四、資料驅動方式

原型只有五種通用節點：`dialogue`、`choice`、`combat`、`reward`、`end`。節點ID、台詞、心聲、選項出口、角色、倍率、起始生命、戰中對話門檻、AI種子、招式權重與獎勵全部在 JSON。執行器不判斷「是不是呂布」或「現在是張飛」，只讀節點類型。

`combat` 目前接既有單挑模型，支持玩家或自動雙方；`opening` 是場內開場對話，`cues` 是只觸發一次的回合／生命門檻對話。每場的新狀態清除上一場修正。未來新增 `debate` 適配器連接現有舌戰模型，沿用同一開場、選擇、勝敗出口、獎勵協定；本次沒有宣稱已支援可玩的資料驅動舌戰。

原型已接「指定關序第一次步兵交手」觸發器，`field` 資料指定兵力、敵將與關序；事件有單次觸發旗標，拒絕後恢復戰場也不會再觸發。後續國線還可擴充「關卡進場、對決前、血量門檻、勝敗、關卡結束」。每個事件採事件實例ID、節點ID與已發獎紀錄保存；正式存檔須保存已鎖定對手出招與隨機狀態，讀檔不重骰、也不再發寶物。示範目前只在記憶體保存，重新入陣會重置本次假資料。

資料載入時檢查版本、角色引用、出口、生命比例、倍率、獎勵ID重複等。畫面輸入以修訂號防止重複點擊；特殊獎勵以唯一ID防止同流程重複入帳。戰鬥結果只能從既有單挑模型產生，畫面沒有「直接勝利」按鈕。
