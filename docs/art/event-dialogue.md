# 事件與委託的對話演出

養成流程的事件入口统一使用 `EventDialogue`。既有 111 則事件保留原敘述、選項、門檻與結算規則，改以旁白、發言、玩家回應、結果及收穫呈現；舊 PendingPanel 已移除。

進入事件時，紅金行旅列移至上方，原養成控制收起；不透明深色對話框位於下方，遮住場景人物的下半身。發言時顯示獨立頭像與姓名，旁白及獎勵不顯示發言頭像。所有對話字帶黑描邊：普通文字白色、人名／道具／作者指定關鍵詞黃色、增加藍色、減少紅色。頭像沿用實際名士素材，主角沿用事件開始時的官階造型。

頂列貼齊視窗上緣，章節牌向下凸出 32px；章節原畫以 SVG 獨立裁切並補完整描邊，避免 CSS 百分比切到尖端。對話時原本金錢區改為事件類型／星數／名稱，靠左排列，四個功能入口不渲染。右側共同參與區退場並設為 inert；結束後恢復一般行旅列與 HUD。

一般對話框為 192px 高，收穫頁 244px（1280×800 舞台）。選項出現時，原對話框保留最後顯示的句子、說話者與頭像；中央另有 580px 寬的深褐色抉擇面板，顯示三個回應與數值預覽。雙人場景在選擇時向左右略讓出空間，避免遮住臉部。Hover 只描亮邊框，不改尺寸或底圖。

長文依標點分頁、最多 70 字；不放繼續鈕或 Enter 提示。點場景、人物區、對話框或頂列均推進一段；選項／演出控制／設定視窗不觸發額外推進，選項頁只能選擇回應。Enter／Space 保留鍵盤操作。

## 內容編排

`EventDef.dialogue` 定義在 `src/contracts/core/dialogue.ts`，由 `content-source/dialogue.ts` 編排並隨內容編譯；不在畫面程式硬寫事件 ID。

- `intro`：逐段 `speaker`、`textKey`、可選 `moves`。角色 0 是主角，1 起依事件 cast 排列；委託的角色 1 為軍吏。`speaker: null` 為旁白。
- `moves`：指定角色、毫秒及路徑。`x` 是 1280px 舞台的百分比，`y` 為垂直位移，`rotate` 為角度，`opacity` 控制退場。每段起終點均由內容指定，動作不循環；未收到新指令的角色維持上一段終點。
- `outcomes`：依選项及可選的成功／失敗條件，編排結算後的動作與發言。
- `keywords`：文字 key，指定該事件額外需要標黃的詞彙。姓名、道具、技能與特性由既有名稱表辨識。

所有角色起初從左右滑入。已正式編排〈深夜相召〉曹操慢慢逼近、〈錯字軍報〉第三選項雙人左右追逐、〈短梯〉樂進跌出画面再滑入；十二位名士初次相遇有個別發言。其餘事件以原旁白及發言者提問銜接選項。新內容可直接增添路徑，不需要另外新增動畫元件。

## 收穫與保存

選項確認只結算一次；收穫依結算前後狀態的實際差額列出，包含支出、薪水、額外金錢、封頂後能力、功績、好感、道具及碎片、領悟、官階與本輪加成。每 420ms 出現一行，每頁最多四行，可立即顯示本頁。讀完最後一頁才繼續下一事件或推進回合。

已結算狀態立即交由既有自動保存處理；若重新整理時該回合已結算而佇列為空，養成頁恢復時推進一次，既不重發獎勵，也不讓已行動回合卡住。演出期間上方功能入口不可切頁，Esc 仍可開啟設定。

## 驗收

開發模式獨立資料入口：`/?art=dialogue&scene=chase`、`scene=fall`、`scene=approach`，以及一般 `scene=commission` / `scene=notable`。`scene=night` 重現〈夜巡異響〉的經驗／成功率／投入等完整預覽。不讀寫玩家存檔。簡化動作依系統減少動畫偏好初始化，也可在演出中切換。

驗證涵蓋全部事件對話入口、無效角色／位移資料、付費及失敗實得、封頂、負好感、重複道具碎片、結算存檔恢复不重領。視覺驗收需另檢查滑入、逼近、追逐、跌落、頭像、長文分頁、選項、逐行收穫及資訊列歸位。
