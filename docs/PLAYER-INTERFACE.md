# 玩家介面與策略管道

本版提供可實際遊玩的魏國畫面，採宣紙底、墨綠導覽、能力色彩與山河插畫。沒有額外的 UI 專用規則或預先寫好的戰鬥結果。

## 玩家流程

1. 天命首頁：生涯、名士記憶、已見結局、四章行旅與下一次入夢。
2. 入夢配置：資質、天賦、攜帶器物與指定玩伴。
3. 行旅：先選行動卡，再確認投入；能力自動成長，經驗另以 1:1 進入學習點。事件仍由玩家選擇應對。
4. 修習堂：技能／特性分類，Lv1–Lv5、下一級效果、能力門檻、實際費用與未學會的傳授來源。不消耗回合。
5. 戰前整備：可以臨時修習，返回後保留技能與指揮草稿；確認出陣後鎖定配置及升級。
6. 戰役：七關獎勵路線、軍勢與糧秣、進退評估、逐回合演出或立即結算。戰敗獎勵減半，仍繼續章節。
7. 夢醒：結局、最終能力、輪迴點與名士碎片，結算後回到天命。

正常四章每章八次行動，共 32 次。投身陣營後從第九回合開始。

## 共用執行管道

```text
React 玩家畫面 ───┐
                  ├─ Session 指令 → 純規則模組 → RunState
RunPolicy 策略 ───┘                           └→ 戰報／結算／存檔
```

入口是 `src/app/session.ts`。`src/app/run-driver.ts` 的 `driveRun(session, policy)` 不使用 React、DOM、計時器或戰鬥演出，只同步呼叫相同指令。

`RunPolicy` 可決定行動、事件選項、學習點運用、三招與指揮配置、是否繼續戰役，也可覆寫投身陣營與選擇上司。修改策略不需要改玩家畫面；調整內容數值會同時影響兩條路徑。

```powershell
npm run dev
npm run sim:fast -- 1000 flag-chaser
npm run sim -- 100 flag-chaser
npm run verify
npm run build
```

`sim:fast` 使用固定 seed 1000 起算、相同初始空白天命，輸出耗時、每秒輪數、實際行動數、各章平均關數與結局分布。這是独立樣本基準；不會把上一輪獎勵自動滾入下一輪。跨輪養成可由呼叫端以 `Session.settle(meta)` 更新天命，再啟動下一個 Session。

## 本版養成行為

- 各屬性經驗自動依成本表換成能力；不足一點及達上限後的餘額保留。原有道具的學費折扣與成本帶調整仍有效。
- 所有上述經驗另以原始入帳量累積學習點，與屬性池獨立。升級只扣學習點。
- 傳授或獎勵首次取得能力直接獲得 Lv1；再次取得免費升一階，最多 Lv5。一般共事傳授仍依原有好感及星階表選擇尚未傳授的項目，不是每回合自動升級。
- 玩家主動升級需要對應能力達標；Lv2–Lv5 門檻為 40／60／75／90。技能基本費用 80／160／300／500，特性為 60／120／240／420，再套能力階級與現有折扣。
- 等級效果倍率為 1／1.2／1.45／1.75／2.1，實際進入玩家技能及特性效果計算。指揮與敵將仍使用自身內容定義。

**數值範圍：** 單一武將 1／1／2／3／5、至少 12 輪滿星，以及零星約四關極限、近全五星輕鬆七關的完整平衡方案，仍在 `WEI-V2-NUMERICAL-DESIGN.md` 與 `balance/wei-v2.proposal.json`。本次未整套套用星階成本、夥伴倍率、戰役敵軍及結局門檻；目前可玩版本不能當作該方案已完成校準。

## 存檔與驗證

天命沿用 `sgd.meta.v1`；本輪使用 `sgd.run.v2`，保存完整 RunState、RNG 游標與最近十二條行旅紀錄，整備草稿也會保存。讀取失敗保留原始本輪資料並提示；儲存失敗會在畫面顯示警告。戰鬥演出只是重播，刷新回到已結算狀態，不會再打一遍同一關。

測試涵蓋 32 次行動、同 seed 確定性、事件中與戰前／開打後序列化續玩、免費傳授與 Lv5 上限、獨立扣款、能力門檻、戰中鎖定及戰役獎勵曲線。瀏覽器另驗證行動成長、事件、戰前升級、配置保留、刷新恢復、戰鬥演出、收兵與魏國入朝；手機寬度下整頁無水平溢出，七關路線可獨立橫向捲動。

相容保留舊 `learnAttr/learnSkill/learnTrait` API 供既有工具遷移；玩家介面與主要策略已使用 `learningOffers/upgradeAbility`。新增策略請使用新入口，不要混用舊手動屬性購買流程。
