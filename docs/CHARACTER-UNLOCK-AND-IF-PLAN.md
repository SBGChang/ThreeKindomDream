# 角色解鎖與同行 IF 擴充計畫書

日期：2026-09-17  
狀態：討論提案，尚未實作。現況以本次讀取的程式為準；下述新增規則與劇情均為本案建議。

> 本文僅保留第一版概念，不作為現行規格。請讀 [全武將解鎖企畫 v4](narrative/CHARACTER-UNLOCK-MASTER-PLAN.md) 與 [固定八章 IF 全案](narrative/IF-STORY-COMPLETE-PLAN.md)。最新版涵蓋 37 人、三國新歷史分流；嚴格維持共同序章＋八章，取消章間短戰役與額外準備節點。衝突處以 v4 為準，遊戲尚未套用。

## 1. 設計主旨

**這一夢與他結緣，下一夢才有機會與他更早同行；當他真的在隊伍裡，故事便因而改變。**

遊戲起初只開放部分角色。玩家在夢中完成救援、擊敗強敵、首次通關、能力成長、官階晉升或取得物品等條件後，永久開放對應角色的抽選資格。重要角色再配置「同行 IF」：未入隊時走原劇本，入隊時改用符合目前陣容的新劇本。

此系統提供三種重玩動機：追求尚未相逢的角色、期待下一夢抽到新夥伴、帶著夥伴重訪熟悉的故事。

## 2. 必須分開的四件事

| 概念 | 意義 | 保存範圍 |
|---|---|---|
| 角色解鎖 | 角色取得進入抽選池的資格 | 跨夢境永久保存 |
| 本局入隊 | 這一夢實際成為玩伴或上司 | 本局 |
| 當夢改命 | 這一夢救援成功、改變人物命運 | 本局 |
| 同行 IF | 角色在隊伍中，因此採用另一套故事 | 本局，於指定劇情節點判定 |

另有既存的星階、好感與指定資格，繼續各自運作；角色解鎖不直接送星階，也不自動給指定權。

核心規則：

1. **解鎖不等於立刻入隊，也不保證下次抽中。** 成功後從下一輪入夢起開放抽選。
2. **角色未解鎖，仍能作為 NPC、敵將及劇情人物出現。** 否則玩家會失去解鎖他的途徑。
3. **已解鎖但本局不在隊伍，仍走原本劇情與檢定。** 不繼承上一夢的救援結果。
4. **故事看整個本局隊伍，不只看當場出戰武將。** 暫時沒上場不能讓人物突然變回敵軍。
5. 解鎖條件達成便確定解鎖，不再追加一次機率骰子；隨機性留在未來抽選。
6. 條件達成並保存後，即使這一夢後來戰敗或提前結束，解鎖也不撤銷。

## 3. 解鎖採兩類，劇情擴充分層製作

| 類型 | 玩家行為 | 額外內容需求 |
|---|---|---|
| 故事結緣解鎖 | 完成指定救援、戰役勝利或劇情結果 | 關鍵成功演出、結緣台詞；指定角色加同行 IF |
| 一般條件解鎖 | 通關、能力達標、升官、取得物品 | 條件、簡短提示、解鎖通知即可 |

故事結緣不一定要先改寫歷史。關羽屬於「救援建立緣分」，呂布屬於「交戰建立認可」。兩者都能在未來同行時改寫劇情。

一般解鎖角色不必配多段前置、特殊結局或完整 IF。若角色與既有敵將／死亡台詞衝突，仍須做最小一致性修正，但不因此擴成專屬故事線。

## 4. 關羽：麥城結緣 → 來世同行

### 4.1 本局沒有關羽

不論帳號是否解鎖關羽，都進入原本荊州失勢、敗走麥城的故事，重新檢查本局準備與救援成果。

現有程式已有以下完整救援條件：

- 赤壁 `S4.A = pact`：訂立互援通航。
- 漢中 `S6.A = corridor`：備妥援路。
- 荊州 `S7.A = rescue`：選擇救援。
- 本章最高通關深度至少 5，取得 `shu.guanyu-rescued`。

**建議第一版以這組條件全部成立作為解鎖點。** 這裡將「檢定完全通過」定義為完成救援所需條件，不額外要求第 6、7 關或蜀線最終通關。若要改成七關全勝，應另列更高挑戰，不能悄悄改掉既有第五關救出人的承諾。

| 結果 | 本局故事 | 跨局解鎖 |
|---|---|---|
| 準備不足或未抵達救援門檻 | 原本敗走與未歸的結果 | 不解鎖 |
| 全部救援條件成立 | 關羽仍經歷敗走，但活著撤離；播放結緣對話 | 首次永久解鎖 |
| 已解鎖後再次救援成功 | 照常保留本局救援結果與對話 | 不重複授予、不刷額外獎勵 |

成功對話草案：

> 舟燈漸遠，麥城的火還映在江面。關羽望著你，緩緩收刀。  
> 「今日若非有你，關某恐怕已無歸路。」  
> 「若有來世，真願能更早與你相識。」

提示：「與關羽的緣分已留下。往後入夢，將有機會與他同行。」

**敗走與戰死分開處理。** 本案採用「敗局仍發生，關羽被救活」的解讀，符合曾讓他沒有戰死的解鎖條件。若成功後仍寫他戰死，便與此條件矛盾。

現有 `S7.B = pact` 與蜀線完成仍決定完整改命收束；救援成功、角色解鎖、完整 IF 結局是三項不同成果。不能因後來未完成和約，就收回已解鎖角色。

### 4.2 本局有關羽：同行版〈這一次，並肩回去〉

這一夢的關羽早已與你相識，是同一位人物；不再生成另一名需要你救援的關羽。

建議主軸：荊州仍面臨斷援與敵軍壓力，但關羽與玩家共同制定撤軍與接應，不再重演「趕到麥城救回陌生故人」。

| 節點 | 同行版內容 |
|---|---|
| 前置章 | 關羽共同檢視通航與援路，回應你們已建立的信任 |
| S7 入章 | 改為共同承擔荊州危局，沒有「關羽失聯」的矛盾敘述 |
| S7.A | 選擇接應軍民或保住退路，取代尋找受困關羽 |
| 戰役 | 仍需作戰；挑戰圍繞接應與撤退，不因帶關羽便自動全勝 |
| S7.B | 商議撤軍後的盟約與整軍，接續本局成果 |
| 後續章與結局 | 移除關羽死亡、為關羽復仇等不成立的敘述 |

對話草案：

> 關羽按住地圖的一角：「這回，你我早已同路。」  
> 「不必來尋關某。今日，一起把人帶回去。」

同行分支有自己的「共同撤援成功」里程碑；不冒記為原線的「救出關羽」。若希望兩條路都能抵達〈桃園再聚〉，以明確條件讓兩種里程碑各自接到合適版本。

第一版建議同行分支的失敗代價放在軍勢、軍民撤離與結局品質，避免既存固定隊伍系統尚無退隊機制，卻在故事中把仍可培養的關羽寫死。

## 5. 呂布：虎牢交鋒 → 聯軍同行

### 5.1 本局沒有呂布

保留董卓麾下呂布登場與虎牢關交戰。玩家完成指定的呂布決戰勝利後，原章節走向照常，只新增他的認可與結緣。

第一版建議以虎牢關第 7 關對呂布的正式決戰勝利作為門檻。某些陣營資料在較早關卡也使用呂布敵將，不能將任意一次遭遇勝利都誤判為最終解鎖。

> 呂布收住方天畫戟，回望了一眼董卓的軍旗。  
> 「與你為敵，倒也痛快。」  
> 「真希望有朝一日，能與你站在同一面旗之下。」

成功即永久解鎖，當局不臨時加入隊伍、不改成投降招募，也不要求玩家之後完成整條國線。

魏、蜀、吳的虎牢章應對應同一個結緣規則；各線敵將 ID 可以不同，但認定的是同一位呂布與同一種決戰成果。

### 5.2 本局有呂布：同行版〈奉先在此，關前易旗〉

入章便確立：這一夢呂布與玩家站在聯軍，董卓軍沒有呂布。不要演成玩家已帶著呂布，敵方呂布打完才突然倒戈。

建議故事結構：

1. 聯軍對呂布的信任仍有疑慮，由玩家與呂布共同回應。
2. 董卓軍因失去呂布改採重兵固守，李傕、郭汜或西涼守軍承擔關防。
3. 呂布可參與破陣，但勝利仍需要玩家調度與戰役表現。
4. 末關替換為西涼主陣，具體敵將與數值在戰役設計時定案。
5. 戰後承接各陣營原有章節出口，並加入第一次並肩作戰的回應。

> 呂布將畫戟指向關上：「這一回，我在你這邊。」  
> 「董卓少了個呂布。你，多了個先登的人。」

必須一起替換：開場、選項、七關中所有相關敵將、單挑與戰役對手、戰報、勝敗演出、教學與章末台詞。不能只有故事寫聯軍呂布，戰鬥卻還在打敵方呂布。

原版與同行版維持相同章節長度、合理相近的挑戰與收益預算；戰鬥內容可不同，帶人不等於跳過關卡或額外領兩份獎勵。

## 6. 一般條件解鎖

以下門檻皆為示例，角色配對與數值需對照成長曲線後定案；不視為已確認的內容名單。

| 類型 | 規則示例 | 觸發與判定 |
|---|---|---|
| 首次通關 | 首次完整完成蜀國線，解鎖一名蜀國角色 | 正式結算確認所屬路線與完成狀態；失敗、放棄不算 |
| 能力達標 | 單局武力本體值達門檻，解鎖武將 | 成長狀態提交後判定；排除戰鬥暫時增益 |
| 官階達標 | 任一夢達到指定文官或武官品階 | 升官正式成立時判定，使用官階 ID／排序規則 |
| 取得物品 | 曾實際獲得指定寶物，解鎖相關人物 | 取得成功時判定；僅看過商店或圖鑑不算 |

預設達到一次就永久保留。物品後來用掉、能力因局結束重置，都不撤銷解鎖。

多項條件要明示是「同一夢全部達成」還是「跨夢曾各自達成」，不可把兩局各一半的本局條件意外拼在一起。第一版優先使用單條件，少量使用明確的 AND／OR。

解鎖由核心的「角色開放規則」負責。成就頁可以同步顯示成果，但不讓抽選系統依賴成就 UI 或成就模組，保留現有成就屬於周邊紀錄的分工。

## 7. 初始名單與抽選規則

### 7.1 初始池必須先能正常玩

開放名單要涵蓋統御、武力、智力、政治的基本養成需要，並能完成所有既有路線；故事解鎖不得要求先抽到被鎖住的本人。

目前蜀國可培養名單是劉備、關羽、張飛、趙雲、諸葛亮、蔣琬，共六位。直接鎖關羽後只剩五位；若其中三位已成為玩伴，上司階段便可能只剩兩人。

**建議補足初始可用人物，維持既有三玩伴＋三上司的設計。** 每國可抽上司在扣除最不利玩伴組合後，仍須能補滿三席；在目前可跨國抽玩伴的規則下，每國至少六名初始可用且符合池條件的上司，是基本安全線。若再鎖諸葛亮，蜀國還要補更多人。

新增人選可從已有劇情人物評估，但具備姓名或立繪不代表已完成可培養角色資料。名單、四維定位、技能、培養內容與美術一併計入工作量。

### 7.2 所有取得途徑共用同一資格判定

| 入口 | 新增規則 |
|---|---|
| 隨機玩伴 | 已載入角色 ∩ 已解鎖角色，再排除已選成員 |
| 指定玩伴 | 已解鎖，而且符合既有指定資格 |
| 隨機上司 | 所屬陣營池 ∩ 已解鎖 ∩ 原有條件，排除隊內成員 |
| 指定上司 | 同上，再套既有自選名額與資格 |
| 特殊招募或後續新入口 | 同樣檢查角色開放規則 |

NPC 出場與敵將生成不受上述限制。關羽即使未解鎖，仍可出現在蜀線與麥城。

隨機抽補必須從已過濾的池中抽；不能只過濾 UI 供玩家選擇的名單。不能在池不足時偷偷用鎖定角色補位。

第一版沿用既有抽選方式，不額外增加首次解鎖必出、保底或強制招募。透過入夢池預覽和既有指定養成，讓玩家知道解鎖後如何相逢；若後續體驗顯示等待過久，再評估機率調整。

## 8. 劇情與世界一致性

### 8.1 用何時的隊伍判定

每個需要改寫的章節在入章時讀取實際隊伍，選定章節版本並保存。本章讀檔、切換出戰名單或查閱手記都沿用同一版本。

關羽若在更早的入朝階段成為上司，到 S7 時也屬於「隊伍有關羽」。呂布若在虎牢之後才加入，不能回頭改寫已完成的虎牢故事。

這項判定不限定角色必須從幼年就在隊伍。各角色若有更早前置場景，也在相應場景到達時判定，避免已入隊仍演初次相識。

### 8.2 一名人物只有一個身分

同一位名士在同場故事中不得同時是隊友與敵人，也不得在敘事死亡後無說明繼續作為隊友活動。

呂布目前有 `enemy:lvbu` 與 `enemy:shu.lubu` 等不同資料識別；新增可培養角色時應建立明確的同人物對應，不靠名稱字串猜測。此對應同時用於敵我衝突檢查。

跨國玩伴沿用夢境設定：這一夢的效忠、出身與相逢時間可以不同。若關羽在魏／吳隊伍，需清理當線涉及敵方關羽的場景；無須憑空為每國加一整章麥城 IF。

### 8.3 多角色不無限擴張劇本

每章指定主要角色分支，其餘人物提供有限的插入對話。必須宣告多個主要角色同時存在時的優先規則或組合版本；資料驗證拒絕未處理的衝突。

第一版完整支援關羽與呂布，兩人的主要改寫位於不同章，可同局成立。後續每加入一位完整同行 IF，都需附上「影響章節與人物衝突表」。

## 9. 玩家介面與回饋

圖鑑至少區分：未解鎖、已解鎖但尚未同行、曾經同行。星階與好感另列，避免將零星誤認為尚未解鎖。

- 未解鎖：顯示解鎖線索；到達相關故事章節後顯示具體要求與進度。
- 解鎖當下：先播成功故事，再顯示一次解鎖卡；存檔不依賴玩家按完動畫。
- 入夢配置：明示哪些角色在本次可抽池、哪些仍需取得指定資格。
- 帶特殊角色入夢：提示「本次部分劇情將因同行者改變」，不提前暴露完整分支。
- 故事手記：區分原線、救援成功、同行版，記錄本局實際看過的版本。

一般條件解鎖採簡短通知，例如「武力達到要求，某某已加入未來入夢的相逢名單」。不強迫每個解鎖都打斷遊戲播放長篇對話。

## 10. 技術落地範圍

本節描述需要新增的責任與資料，欄位名稱可在實作時調整。

| 區塊 | 現況與所需工作 |
|---|---|
| 跨局狀態 | 新增已解鎖角色與首次解鎖來源；與星階、碎片、共同通關紀錄分開 |
| 解鎖規則資料 | 定義預設開放與條件開放，支援故事成果、指定戰役勝利、通關、能力、官階、物品 |
| 解鎖判定 | 訂閱正式狀態變更，授予一次；保存條件證據與規則版本以利追查 |
| 入夢快照 | 把本局可使用的解鎖結果固定於 `metaSnapshot`，當局新解鎖不倒灌當局抽選 |
| 抽選與指定 | `roster-query.ts`、`roster.ts`、`dream-entry.ts` 共用資格；命令端也驗證 |
| 劇情條件 | `StoryRequirement` 現在只有 choice／milestone；新增隊伍判定能力 |
| 章節分支 | 現有入章、選項、里程碑與章末需能共同選用完整章節版本，而非只換 aftermath |
| 戰役分支 | 現有 `battleVariants` 主要替換 `briefKeys`；新增能替換敵將、遭遇與演出的戰役配置 |
| 呂布角色內容 | 本次查到的呂布主要是敵將資料；須補正式可培養名士、養成與隊友使用內容 |
| 存檔與回放 | 保存解鎖授予紀錄、章節版本與必要識別；固定種子與相同快照仍可重播 |
| 驗證工具 | 加入池容量、循環解鎖、敵我同人物、分支覆蓋與引用有效性檢查 |

目前程式已有關羽救援里程碑；早期 `docs/architecture/34_story.md` 仍記載原型未套用，因此本案不以該段舊狀態判斷開發起點。目前 `save.ts` 寫入版本為 4；實作時另升版本與提供遷移，不能直接照舊文件的版本號處理。

### 10.1 保存時序

建議流程：結果確認 → 更新本局成果及永久解鎖 → 一次保存包含兩者的狀態 → 呈現故事與解鎖通知。

劇情動畫只負責展示。關卡勝利已正式保存後，就算關閉遊戲，也不應因尚未按完台詞而失去解鎖。重送結果、讀檔與重播通知均不得重複授予。

原本的本局 `metaSnapshot` 保持不變；永久進度須由實際持有跨局資料的 session／存檔流程寫入，避免結算用舊快照覆寫剛得到的解鎖。此項是第一階段必須查明並驗證的接線工作。

### 10.2 舊存檔建議

- 已開始的夢保持現有隊伍及劇情策略；不在半途強插錯過的同行前置，新系統完整套用於新夢。
- 對舊玩家有明確培養、共同通關或目前已入隊的角色，保留可用權並記錄為遷移授予。
- 不因資料中存在零值圖鑑列便推定玩家已取得角色；空白預建列須與實際進度區分。
- 舊紀錄若能證明已完成新解鎖條件，可補發；沒有證據的故事條件不憑空推定。
- 遷移失敗保留原存檔，不用清空進度解決。

## 11. 製作階段與交付

| 階段 | 工作 | 可檢查的成果 |
|---|---|---|
| A：基礎規則 | 定案首發名單、解鎖資料、保存時機、初始池補足與遷移 | 新帳號可正常組滿隊伍；一般條件能永久解鎖 |
| B：關羽完整流程 | 現有救援接解鎖、結緣演出、同行章節與後續收束 | 救援解鎖 → 下局抽中 → 劇情改變全程可玩 |
| C：呂布完整流程 | 可培養角色、三國虎牢解鎖識別、聯軍版本與敵將替換 | 呂布在隊時，虎牢所有相關內容沒有敵方呂布 |
| D：擴充與整理 | 一般條件角色、圖鑑進度、手記、提示與數值調整 | 通關／能力／官階／物品至少各一條實際規則 |

本波交付建議包含關羽與呂布的完整同行 IF，加四種一般解鎖入口。其他救援角色可沿用規格後續擴充，不在第一波承諾所有名將都具備完整改寫線。

在初始名單與新增人物內容量尚未確定前，先按上述里程碑估工作量，不給缺乏依據的固定工期。

## 12. 驗收清單

1. 新帳號抽不到鎖定的關羽、呂布，但故事與敵將仍能正常出現。
2. 每國在最不利玩伴組合下，仍能抽滿既定上司席次，且無重複人物。
3. 關羽救援條件全部成立後只授予一次；後續戰敗、收兵或讀檔不撤銷。
4. 已解鎖但未帶關羽，仍須重新通過本局麥城救援，不自動成功。
5. 已帶關羽，開場、選項、戰役文案、章末與結局均採用同行邏輯。
6. 虎牢正式呂布決戰勝利才解鎖；早期遭遇、敗北、跳過不誤發。
7. 已帶呂布，所有當章敵將、單挑與戰報均與聯軍版本一致。
8. 呂布與關羽同隊可連續走各自分支，沒有其中一個覆蓋另一個的問題。
9. 一般解鎖達成後永久保留；暫時能力增益、看過物品與失敗結算不誤判。
10. 指定與隨機抽補皆不能繞過鎖定；當局新解鎖最早下局生效。
11. 關卡結果保存後立刻重啟，仍保留解鎖與正確分支；不重複發獎。
12. 舊存檔不失去已有角色、培養進度與進行中的夢。

## 13. 本稿採用的設計決定

以下為讓方案能具體討論而採用的建議，並非追加的既定需求：

- 關羽成功時仍敗走，但活著撤離；在既有第五關救援門檻解鎖。
- 呂布在虎牢第七關正式決戰勝利後解鎖，各國虎牢共用人物解鎖結果。
- 解鎖當下永久保存，下一夢開始進池；不自動送本局角色或指定權。
- 隊伍包含玩伴與上司，並在相關章節入章時固定劇情版本。
- 同行關羽仍面臨戰役風險，但第一版不新增角色永久死亡與退隊機制。
- 維持三玩伴＋三上司，先補足初始名單再鎖人。
- 第一波完整同行 IF 做關羽與呂布；一般條件解鎖採共用規則、小量內容。
